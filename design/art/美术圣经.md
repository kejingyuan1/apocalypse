## 1. 世界观与基调（World & Tone）

**核心命题**（§0 概念）：在 18×18 像素网格上，从避难所建成末日堡垒；周期性挡尸潮 + 实时突袭他人——**空间布局即战略**。

**视觉如何传达"绝望中的秩序感"**：
- **网格即秩序**：堡垒严格对齐 32×32 栅格，墙体/地板横平竖直；倾斜/错位只出现在破损（叙事：被尸潮冲击的裂痕 + 动态腐蚀贴片）。
- **冷暖疆界**：堡垒内 = 暖橙光池（§11 #5 `AMBER_WARM`）；堡垒外 = 冷蓝月色 + 棕绿废土（§11 #2/#6）。玩家靠"进入光池"获安全感。
- **留白即稀缺**：暗部占 60%–70%，仅 30%–40% 为可辨识细节；霓虹辉光（冷蓝能源/暖橙威胁）作稀缺高光。
- **基调分级**：运营期 = 沉稳压抑（棕绿基底）；防御期 = 高压橙红脉冲；反攻期（PVP）= 侵略性全屏警示。靠光色 + 抖屏强度切换，不换美术风格。

**禁止项**：卡通圆润、高饱和糖果色、柔光晕染、照片感材质、非整数像素缩放。

## 3. 像素密度与分辨率规范（Pixel Density & Resolution）

> **基础 tile = 32×32 px（作者分辨率）**，主理人裁定（§11#3）。世界最大堡垒 = **18×18 格**（§0/§7）= 576×576 px；战场含堡垒外 spawn 余量，约 24–30 格见方。

### 3.1 关键尺寸（含"俯视微厚"厚度）

| 资产类别 | 作者尺寸（px） | 说明 |
|---|---|---|
| 地形 Tile | 32×32 顶部 + 4px 侧面厚 | **俯视微厚**：顶面 32×32，南/东向 4px 侧面厚度（§11#9·主理人裁定保持） |
| 城墙/小件 | 32×32 + 4px 厚 | 1–4 格拼接 |
| 房间模块 | 按 §7 占格 ×32，带侧面厚 | 集装箱/预制板拼装感（§11#7） |
| 玩家居民 | 24×32 | 略小于 tile，留行走边距 |
| 普通行尸 | 24×32 | 同居民体型，靠姿态区分 |
| 快速尸 | 20×28 | 更瘦长、前倾 |
| 装甲尸 | 32×40 | 越格，压迫感（带厚侧面） |
| 喷吐尸 | 24×32 | 臃肿腹 |
| 物品/资源图标 | 32×32 | UI 用（屏幕空间，不受缩放影响） |
| 特效（光/血/腐蚀） | 32×32 / 64×64 | 加色混合精灵 |

### 3.2 内部分辨率与整数缩放

| 目标 | 设计分辨率 | 整数缩放档位 |
|---|---|---|
| PC / 大屏 | 640×360（16:9） | 2×(1280×720) / 3×(1920×1080) |
| 平板（16:10） | 640×400 | 2× / 3× |
| 手机竖屏 | 360×640（9:16，UI 重排） | 2× / 3× |

- **渲染策略**：Godot 视口 `stretch_mode = viewport`，`stretch_aspect = expand`；世界按设计分辨率渲染，**整数倍**放大到设备分辨率，杜绝非整数缩放的像素抖动。
- **像素吸附**：所有 Tile/精灵 `texture_filter = Nearest`（关 mipmap/线性过滤），硬边像素。
- **可读性保障（32×32 下）**：靠①整数缩放使 tile 在设备上物理放大（1080p 下 32px×3=96 设备 px/tile）；②粗剪影 + 图标系统；③HUD/小地图在屏幕空间以更高分辨率绘制——**不靠放大 tile 本身**（遵循 §11#3 + #10）。

### 3.3 相机缩放层级（Camera Zoom）

| 层级 | camera.zoom | 可见范围（640×360 / 32px tile） | 用途 |
|---|---|---|---|
| 总览 OVERVIEW | 0.6 | ≈ 33×18 格（含 18×18 堡垒+外缘） | 布防全局、PVP 看敌我全图 |
| 常规 NORMAL | 1.0 | ≈ 20×11 格 | 日常经营主视角 |
| 细节 DETAIL | 1.5 | ≈ 13×7 格 | 查看房间内居民/资源 |
| 限制 | clamp [0.6, 1.8] | — | 防过度缩放丢失像素感 |

- 缩放过渡：步进式（固定档），切档 0.15s 仅用于镜头位移缓动，不用于缩放插值模糊。

## 4. 光照与氛围（Lighting & Atmosphere）

**基调**：末日昏暗。环境光整体压低，靠"人造光池 + 霓虹辉光"制造焦点（§11#1）。

### 4.1 环境光分层
- **室外基准**：冷蓝 `#2A3346`，强度低（≈ 0.35），夜幕。
- **室内暖光池**：`AMBER_WARM` 光源色，半径 3–4 格，强度 0.8–1.0，衰减用**阶梯量化**（贴合像素）。
- **室内外交界线**：门/窗硬边明暗交界，强化"进堡垒=安全"。

### 4.2 动态光源（Godot Light2D，限预算）
| 光源 | 颜色 | 行为 | 移动端预算 |
|---|---|---|---|
| 能源室辉光 | `ENERGY_CYAN` | 常亮脉动（2s 呼吸） | ≤ 2 常亮 |
| 武器开火 | `WEAPON_MUZZLE` | 瞬态暖橙闪光 | 单帧按需 |
| 营火/焊接 | `AMBER_HI` | 噪声闪烁 | ≤ 1 |
| 丧尸感染辉光（眼） | `INFECT_GLOW` | 极弱自发光，不投光 | 不计入光源数 |
| 护盾 | `ENERGY_CYAN` | PVP 护盾淡蓝膜 | 事件态 |

- 同屏动态 Light2D ≤ **6**（移动端 ≤ 4），超出用"加色精灵伪光"代替。

### 4.3 像素体积光 & 厚涂硬阴影（§11#1/#4）
- **光柱**：半透明斜向矩形精灵，`ADD` 混合，量化 3–4 级 alpha 阶梯模拟体积光。
- **辉光/Bloom**：`WorldEnvironment` 轻量 Bloom（高 threshold、低 intensity），仅作用于冷蓝/暖橙高亮像素（"废土霓虹"）；移动端可关。
- **雾**：`FOG` 低 alpha 全屏 + 远景额外层，造纵深。
- **阴影**：**厚涂硬阴影块**——方向光投影呈大块面硬边（无柔化），体积靠 2–3 级明暗块面（非渐变）表现（§11#4）。

### 4.4 动态腐蚀贴片（Dynamic Grime · §11#8）
- **系统**：受损墙体/血迹/锈迹作可叠加 decal 层，随结构受损度提升而**扩散/加深**。
- **规格**：腐蚀图集 32×32，3–4 帧 @8fps 表现"蔓延"；血迹单帧静态；锈迹低频闪烁。
- **叠加规则**：decal 层独立于结构层，按房间受损状态（0–100%）混合 alpha；用于叙事（废墟贴片，§2.4 Narrative）+ 战损反馈。
- **责任**：资产由 Phase 4 产出；图层/混合由 程基岩在渲染管线落地。

- **差异化铁律**：① 先看体型/姿态/占比（Walker 正常、Runner 瘦长前倾、Brute 越格巨大、Spitter 臃肿）；② 再看颜色（苍白=Runner，深橄榄=Brute）；③ 最后看动效（Runner 快、Brute 慢震）；④ **所有丧尸威胁色统一橙红 `INFECT_GLOW`**（§11#5），但**禁止仅靠橙红区分类型**——必配剪影 + HUD 小地图形状（●Walker / △Runner / ■Brute / ◆Spitter）。⑤ **首发范围（主理人裁定）**：普通/快速/装甲/喷吐（Spitter）首发；自爆 Bloater 延至延伸层，不首发。

## 7. UI 视觉规范（UI Spec）

> 像素 UI 原则：**粗边、少渐变、图标优先、信息分层**。响应式：PC 底部停靠栏+热键；移动端底部大按钮栏（触摸目标 ≥ 48dp）。

### 7.1 通用像素 UI 原则
- **边框**：2–3px 硬边双层框（`UI_BORDER` 外 + `UI_BORDER_LT` 内浮雕），禁 1px 细线（小屏糊）。
- **字体**：像素点阵（8×8 / 10×10）；正文 ≥ 10px@1×，标题 ≥ 14px@1×；移动端 +2px。
- **图标密度**：功能图标 ≥ 24×24，重要操作 ≥ 32×32；图标必带文字标签/长按提示（可访问性）。
- **数据双通道**：资源/血量用**条形 + 数字**，不单靠数字；进度用分段像素条。
- **可读性优先（§11#10）**：敌我/资源/状态在最小 UI 尺寸下靠"图标 + 形状 + 文字"一眼可辨，不依赖颜色。

### 7.2 资源 HUD（对齐 §7/§13：3 资源 + 人口）
- 顶部资源条：废料(`#8A8F9C`)/晶体(`#48B6E8`)/生物质(`#7E8856`)/人口(`#E8923D`)，各配 §2.7 图标 + 数字 + 涨跌箭头（箭头=非色彩通道）。
- **三态 HUD（§10.3）**：运营 / 防御 / 反攻 用标签页区分，配图标 + 文字（不单色）：运营=橄榄/暖橙（静）、防御=暖橙（警）、反攻=暖橙（攻，配进攻箭头图标）。

### 7.3 各界面要点
| 界面 | 布局 | 关键规则 |
|---|---|---|
| **建造菜单** | 网格模块卡（图标+名+造价） | 按 §6.1 分级/§6.2 符号分组着色；拖动/点击放置 |
| **波次预警** | 全屏边缘**暖橙**脉冲 vignette + 顶部"尸潮来袭"条 + skull 图标 | **非纯红**：skull 图标 + 轻抖 + 音效（§11#5 暖橙） |
| **PVP 攻击界面** | 敌堡高亮描边 + 目标准星 + 伤害飘字 | 敌我以**边框色+旗帜图标**区分（己=冷蓝 `ENERGY_CYAN` / 敌=暖橙 `DANGER_ORANGE`），不单靠颜色 |

### 7.4 响应式适配
- PC：鼠标+键盘热键，高密度。移动：底部固定操作栏（建造/编队/镜头）按钮 ≥ 48×48dp；资源条可折叠。Web：同 PC，限最大画布，禁用右键冲突。

## 8. 动效原则（Animation Principles）

> 像素动画**步进式（无平滑插值）**，靠"停帧（hold）"造节奏与省预算。

### 8.1 帧率基准
| 类型 | 帧率 | 说明 |
|---|---|---|
| 环境/待机（Idle、火苗、辉光、腐蚀蔓延） | **8 fps** | 省预算、呼吸感 |
| 角色/丧尸行走、常规动作 | **12 fps** | 标准 |
| 开火/受击/关键 UI 过渡 | **24 fps**（或单帧闪） | 仅瞬态高光 |

- 工程内锁定动画帧率（SpriteFrames / AnimationPlayer `speed` 换算），不依赖设备刷新率。

### 8.2 关键动效语言
| 动效 | 规格 |
|---|---|
| **丧尸行走** | Walker 6 帧@12fps（拖步+躯干晃）；Runner 4 帧@18–20fps（窜）；Brute 4 帧@8fps（沉重+落地拉长）；Spitter 4 帧@12fps |
| **武器开火** | `WEAPON_MUZZLE` 闪光 3 帧@24fps + 后坐 2 帧 + 抛壳 1 帧；微抖 |
| **建造放置** | "落入"1 帧 + 尘土 4 帧@8fps + "吸附"弹（scale 1.0→1.1→1.0 单帧） |
| **屏幕震动/受击** | 受击：白闪剪影 1–2 帧；震屏 trauma 模型，最大偏移 8px@1×，衰减 0.3s；伤害越大 offset 越大 |
| **UI 反馈** | 按下：下沉 1px + 边框反色 1 帧；成功：✓ 弹 2 帧；警告：边框脉冲@8fps |

### 8.3 动效禁忌
- 不做补间平滑位移（破坏像素感）；用整数像素步进。
- 不滥用全屏抖屏（仅波次/PVP 用，日常经营禁用，防眩晕与移动端不适）。

## 9. 可访问性基线（Accessibility Baseline）

> 本节省略详细分级（Phase 3 由 art-director + 主理人做 Basic/Standard/Comprehensive/Exemplary 分级）。此处给**全线必须遵守基线**。

### 9.1 色盲友好（Colorblind-Safe）
- **铁律**：红/橙/绿**不得**作唯一区分通道；所有语义必叠加**形状/图标/文字/图案**。
  - 低血量 = 暖橙条 (DANGER_ORANGE) + ❤图标 + 脉冲 + 音效，不靠第二层红色。
  - 安全绿/危险橙资源 = 配 ✓/⚠ 图标。
- **推荐编码对**：蓝 `#48B6E8` / 黄 `#EAC23A` 对全体 CVD（红绿蓝黄四型）安全，优先用于通用信号。
- **小地图丧尸分型**：用形状非颜色（●Walker / △Runner / ■Brute / ◆Spitter，见 §5.2）。
- **威胁色统一暖橙**（§11#5）但必配 skull/准星图标，防与"成功绿"混淆。
- Phase 3 提供**色盲模拟预览开关**（deuteranopia / protanopia / tritanopia）。

### 9.2 对比度最低标准（WCAG 2.1 AA）
| 内容 | 最小对比度 |
|---|---|
| 正文文字 vs 背景 | **≥ 4.5:1** |
| 大文字（≥18px 或 ≥14px 粗） | ≥ 3:1 |
| UI 组件/图形/图标边界 | ≥ 3:1 |
| 禁用状态可降至 | ≥ 2:1（仍须可辨） |

- 本圣经调色板已校：`TEXT_PRIMARY #ECEEF5` on `UI_BG #1E2230` ≈ 13:1，达标。

### 9.3 关键信息的非色彩通道（Non-Color Channels）
- **图标/符号**：每类信息专属图标（资源/房间/威胁/状态）。
- **文字标签**：图标必配文字或 tooltip。
- **位置/布局**：危险信息固定区位（顶部预警条），不靠颜色引导视线。
- **图案**：危险区用黄黑斜纹（`WARN_YELLOW` 斜杠），不单靠底色。
- **动效/音频**：预警用脉冲 + 音效双通道；受击用白闪 + 抖屏。
- **可读性优先（§11#10）**：32×32 小尺寸下，所有敌我/资源/状态以"剪影+图标+形状"确保一眼可辨。
- **可配置**：Phase 3 提供"高对比模式""大字体""减动效（关抖屏）"开关。
