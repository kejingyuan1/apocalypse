## 1. 系统概述

建造系统让玩家在 **18×18 网格**上规划、放置、移动、升级、拆除房间，是「空间即策略」（P1）支柱的承载核心。玩家通过布局决策——房间朝向、邻接关系、占地取舍——将"建造"从传统模拟经营的装饰，升级为可计算、可博弈的策略核心，区别于纯塔防与纯经营。

一句话定义：**建造系统 = 把 18×18 栅格变成玩家可编辑的战略棋盘**。

---

## 2. 设计目标与验收标准

### 2.1 设计目标
- G1 网格放置零歧义：坐标唯一、占用明确、预览即时
- G2 面积矩阵制造稀缺决策：大房间挤占战略位，小房间填空连线
- G3 三端输入统一抽象：PC / 移动 / Web 共用同一套 GridCommand，跨端体验一致（P5 低门槛高深度）
- G4 战斗锁定保证公平：PVE 波次 / PVP 对战进行中，本方布局不可改建
- G5 成长可见：从 1 房间到 18×18 有清晰里程碑（P3 看得见的成长）

### 2.2 验收标准（MVP 门控）
| 编号 | 验收项 | 通过条件 |
|---|---|---|
| AC1 | 基础循环 | MVP 内可完成「放置→守→扩张」最小循环 |
| AC2 | 六类基础房间 | 居住/能源/武器/生产/防御/城墙均可在任意端放置 |
| AC3 | 冲突反馈 | 重叠/越界/资源不足/战斗锁定均给出清晰 UI 反馈 |
| AC4 | 战斗锁定 | 波次或 PVP 进行中，建造坞置灰且无法提交放置 |
| AC5 | 跨端一致 | PC 与移动端放置结果在服务端完全一致 |

## 3. 核心机制

### 3.1 网格坐标模型
- 世界 = 18×18 cell，坐标 `(col, row) ∈ [0,17] × [0,17]`
- 每 cell 单一占用：映射 `cell → room_id | empty`
- 房间占矩形区域 `[(c0,r0) .. (c0+w-1, r0+h-1)]`，`w×h` 取自面积矩阵（§5.1）
- 堡垒可用网格随等级门控（§5.2），未解锁区域不可放置

### 3.2 放置规则（Place）
触发条件需**全部满足**：
1. 目标区域全部 cell 为 `empty`
2. 资源（废料/晶体/生物质）充足
3. 当前非战斗锁定状态（非波次进行中 / 非被 PVP 进攻中）
4. 房间数未达当前等级上限（§5.2）
5. 目标区域完全落在当前等级可用网格内

放置成功后：写入 `cell→room` 映射 → 触发邻接重算 → 扣资源 → 播放置动效。

### 3.3 移动 / 拆除（Move / Demolish）
- **移动**：拆旧区域 + 放新区域合并为**一次事务**，任一步失败整体回滚
- **拆除**：
  - 返还资源 = 原造价 × `α`（损耗率，建议 `α=0.5`）
  - 冷却 `Cd`（建议 30s，防止频繁重构博弈）
  - **指挥核心（Command）不可拆**（被毁仅重置至 Lv2，见概念 §9.3）
- **升级**：消耗资源提升房间等级，增强产出/防御/供能，**不占新格**（对冲 R5）

### 3.4 占用校验（Occupancy Validation）
| 校验项 | 失败处理 |
|---|---|
| 重叠（目标区有非 empty cell） | 拒绝，高亮冲突 cell |
| 越界（超当前等级可用网格） | 拒绝，HUD 暖橙描边（⚠ 图标）+ "需先升级堡垒" |
| 资源不足 | 建造卡按钮禁用，显示差额 |
| 战斗锁定 | 建造坞置灰，"战斗中不可改建" |

### 3.5 邻接判定（Adjacency Bonus）
互补房间相邻触发加成（示例规则，详细数值待平衡 GDD）：
- 能源 ⊕ 武器：射速 +15%（半径内）
- 能源 ⊕ 生产：产出 +10%
- 实验 ⊕ 武器：解锁"超载"隐藏 combo
- 防御 ⊕ 城墙：减速光环范围 +1 格

## 4. 玩家接口（三端统一抽象层）

> **视觉一致性声明**：HUD 越界 / 占用校验反馈统一用暖橙描边（DANGER_ORANGE #E8762E）+ ⚠ 图标提示，不引入第二层红色 UI（如红色框），遵循《美术圣经》§2.3 单层暖橙铁律。

### 4.1 抽象动词（P5 低门槛高深度）
统一为 5 个动词，各端仅做输入翻译：
`Select / Place / Move / Upgrade / Demolish`

### 4.2 各端适配
| 端 | 输入方式 | 关键适配 |
|---|---|---|
| PC | 鼠标点击选中 + 拖拽预览 + 热键（B 建造坞 / R 旋转） | 高信息密度，悬停预览 |
| 移动 | 底部操作栏 + 拖拽吸附 + 长按弹参数 | 触摸目标 ≥ 48dp，网格吸附防误放 |
| Web | 同 PC，限最大画布 | 禁用右键菜单冲突 |

### 4.3 统一指令结构
所有端输入归一为：
```
GridCommand {
  type: Place|Move|Upgrade|Demolish
  roomType: Wall|Housing|Energy|Turret|Production|Medical|Storage|Defense|Lab|Command
  cells: [(c,r), ...]      // 目标区域
  rotation: 0|90|180|270   // 仅多格房间可旋转
}
```
客户端仅发送 GridCommand，**所有校验以服务端为准**（引用概念 R2 防作弊）。

## 5. 关键数值

### 5.1 面积矩阵（引用概念 §7）
| 房间类型 | 尺寸(宽×高) | 占格 | 功能定位 |
|---|---|---|---|
| 城墙 Wall | 1×1 | 1 | 阻挡/延长僵尸路径/拼迷宫 |
| 人口居住 Housing | 2×2 | 4 | 人口上限（劳动力/防守员） |
| 能源 Energy | 2×2 | 4 | 半径供能，断能降级 |
| 攻击武器 Turret | 2×2 | 4 | 火力点，需射界 |
| 生产 Production | 3×2 | 6 | 持续产出资源 |
| 医疗 Medical* | 2×3 | 6 | 战斗中修复房间/单位 |
| 仓储 Storage* | 3×2 | 6 | 提升资源软上限 |
| 防御 Defense | 3×3 | 9 | 掩体/减速/范围拒止 |
| 实验 Lab | 3×3 | 9 | 解锁科技分支 |
| 指挥 Command** | 4×4 | 16 | 堡垒核心，被毁=失败 |

`*` 延伸层　`**` 全游戏唯一，初始即存在

### 5.2 生长曲线门控（引用概念 §8）
| 堡垒等级 | 可用网格 | 房间数上限 | 解锁内容 |
|---|---|---|---|
| Lv1 | 6×6 | 4 | 居住+生产+城墙 |
| Lv2 | 8×8 | 7 | 能源+防御 |
| Lv3 | 10×10 | 11 | 武器+实验 |
| Lv4 | 13×13 | 16 | **解锁 PVP 出征**+医疗 |
| Lv5 | 15×15 | 20 | 仓储+多线威胁 |
| Lv6(Max) | 18×18 | 30 | 满级+赛季目标 |

升级触发：每存活 3 波自动 +1 级；或消耗资源提前申请。资源门槛指数增长（≈1.6×/级）。

## 6. 边界与异常

| 场景 | 处理 |
|---|---|
| 越界放置 | 拒绝 + HUD 暖橙描边（⚠ 图标）+ "需先升级堡垒" |
| 重叠放置 | 拒绝 + 冲突 cell 高亮 |
| 资源不足 | 建造卡禁用 + 显示差额（废料/晶体/生物质） |
| 战斗锁定 | 波次/PVP 进行中建造坞置灰，"战斗中不可改建" |
| 拆除指挥核心 | 拒绝（核心不可拆） |
| 断线重连 | 布局以服务端快照为准，客户端重建 |
| 邻接加成失效 | 房间被拆/能源断供 → 即时移除对应 buff |

## 7. 依赖系统

| 依赖系统 | 对本系统的影响 |
|---|---|
| 经济系统 | 放置/升级/拆除消耗与返还废料/晶体/生物质（§5 数值） |
| 能源网络 | 房间需落入能源半径才启用；断能降级（影响产出/防御） |
| 波次系统 | 波次进行中锁定布局（§6 战斗锁定） |
| 实时 PVP | 反攻期（进攻方）与防守期（被攻）均锁定本方布局 |

---

## 8. 设计风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| R5 | 后期格子填满后无决策（支柱漂移） | ① 升级替代扩张（房间升级不占新格）；② 邻接协同奖励（布局优化持续有收益）；③ 武器射界/视野限制（位置仍关键）；④ 赛季重置/重构活动 |
| R4 | 跨平台操作不一致（移动端难精准放格） | 网格吸附 + 缩放（美术圣经 §3.3）+ 拖拽长按（§4.2） |
| R2 | 作弊（客户端篡改布局） | 所有 GridCommand 服务端校验，客户端仅发输入 |
| 协同风险 | 多端布局不一致 | 服务端为唯一真相源，客户端仅渲染快照 |
