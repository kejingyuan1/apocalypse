# 离线防御 AI 系统 GDD（Game Design Document）

> 阶段：Phase 2 系统设计（第七个系统 · 延伸层 · PVP 公平性关键支撑）
> 服务支柱：P2 双线威胁（Dual Threat）｜ 协同支撑 P4 实时对抗的快感（Thrill of Real-time Conflict）
> 对应核心动词：Defend（布防）（离线托管态）
> 依赖系统：建造系统（布局锁定/面积矩阵）/ 经济系统（3 资源/软上限/离线衰减/出击成本）/ 波次系统（寻路/破墙/开火模型）/ 能源网络系统（供电判定/断电降级）/ 科技实验系统（防守端科技）/ 实时 PVP 对战系统（MMR/收益衰减/离线护盾/掠夺公式）/ 美术圣经（战报视觉/色盲友好）
> 文档负责人：design-strategist（文策渊）
> 备注：本系统为延伸层（概念 §6.2 ·「离线防御 AI：玩家离线时堡垒自动防守、护盾机制」）。它是 PVP 公平性的关键支撑（概念 §10.2 / PVP §3.5）：玩家离线/断线时遭 RaidCommand 进攻，服务器用**确定性 headless 模拟**驱动其堡垒自动迎战。本系统与「在线防守（DefendCommand）」「波次 PVE 防御」「离线护盾」完全同源，避免离线被双重惩罚或双重豁免。承接《游戏概念文档》§2.3/§6.2/§10.2/§12、《建造系统 GDD》《经济系统 GDD》《波次系统 GDD》《能源网络系统 GDD》《科技实验系统 GDD》《实时 PVP 对战系统 GDD》与《美术圣经》。

## 1. 系统概述

离线防御 AI 是末日堡垒在 **玩家离线 / 挂机 / 断线** 时，由服务器权威驱动的**确定性 headless 模拟防御引擎**：当防守方未主动迎战（未在和平窗口外手动操作 DefendCommand）却遭到其他玩家 RaidCommand 进攻时，服务器基于该玩家**已保存的布局快照**（房间类型/坐标/等级、能源配置、科技加成、预设自动开火优先级），复用波次系统的寻路 / 破墙 / 开火模型 + 能源系统的供电判定 + 科技系统的防守端加成，结算一场无人操作的防守战，并产出「房间损毁 / 资源损失」结果。

一句话定义：**离线防御 AI = 把"布防(Defend)"从真人手动操作降级为服务器权威、可审计、确定性重放的 headless 托管——用与在线防守/波次 PVE 完全同源的战斗模型，保证离线者"弱于在线但不被清零"，杜绝双重惩罚/双重豁免（P2 双线威胁公平）。**

> **与三条既有逻辑的同源关系**（本系统铁律）：
> - **同在线防守（DefendCommand）**：复用同一套战斗模型（寻路/A*/破墙/开火/电网/科技）；唯一差异=离线 AI 不允许手动微操（仅用玩家预设的 `SetAutoPriority` 优先级），且掠夺结算用 `K_online=0.10`（PVP §5.5）。
> - **同波次 PVE 防御**：headless 模拟的寻路/破墙/开火内核直接复用波次系统 §3.4 的 A* + breach 模型与 §5.3 建筑承伤 HP 表；离线 PVE 托管与离线 PVP 托管共用同一模拟内核（概念 §2.3「自动防御 AI 托管」）。
> - **同离线护盾**：护盾激活时目标不可被选中（PVP §3.3/§5.3），Raid 直接跳过，零损失；护盾外离线损失封顶 ≤5% 资源（由 `K_online=0.10` 落实，PVP §5.5 逐字）。

## 2. 设计目标与验收标准

### 2.1 设计目标
- G1 离线安心：离线/断线被攻，资源损失封顶 ≤5%（护盾外），杜绝"睡觉被搬空"（承接概念 §10.2 / PVP §3.5，引用 R1）
- G2 公平同源：离线 AI 与在线防守、波次 PVE 防御复用同一战斗内核，避免离线被双重惩罚或双重豁免（本系统铁律）
- G3 确定性可审计：同输入同输出，服务器权威 headless 模拟，结果可重放/可审计，防作弊（引用概念 R2）
- G4 离线不入劣势黑洞：离线 AI 用与在线相同的科技/电网效果（缺的只是微操），不额外降罚（避免离线必败崩溃）
- G5 平滑接管：模拟中途玩家上线，无缝转交在线 DefendCommand，无状态撕裂（引用 PVP §3.6）
- G6 三端一致：PC / 移动 / Web 同一 OfflineDefenseCommand 预设抽象，落盘/模拟逻辑仅服务端（P5 低门槛高深度）

### 2.2 验收标准（延伸层门控）
| 编号 | 验收项 | 通过条件 |
|---|---|---|
| AC1 | 触发正确 | 仅当玩家离线/挂机/断线 且 收到 RaidCommand 且 未处护盾 且 未处波次期 且 Lv≥4 时走离线 AI；护盾激活/Raid 跳过/ Lv<4 不触发托管 |
| AC2 | 同源战斗 | headless 模拟的寻路/破墙/开火/电网/科技与波次 PVE、在线 PVP 防守用同一份服务端逻辑，无离线专属战斗数值 |
| AC3 | 确定性 | 同 (布局快照 + 进攻方 roster + seed) 输入，三次独立服务器重放结果 bit 一致（防作弊审计通过） |
| AC4 | 损失封顶 | 护盾外离线资源损失 ≤5% 存量实测达标（由 `K_online=0.10` 体现）；护盾生效期零损失 |
| AC5 | 无双重惩罚 | 离线修复成本 = 原造价 ×0.5（与波次 §5.5 / 建造 §3.3 对偶），不叠加离线专属额外惩罚 |
| AC6 | 上线接管 | 模拟中途玩家上线，控制权在 tick 边界转交 DefendCommand，无重模拟、无状态撕裂 |
| AC7 | 快照权威 | 仅服务端最新布局快照可用于模拟；客户端提交与 server 不符的快照被拒（R2 兜底） |
| AC8 | 三端一致 | PC / 移动 / Web 同一 OfflineDefenseCommand 预设，在服务端结果完全一致 |

## 3. 核心机制

### 3.1 触发条件（何时走离线 AI）

离线防御 AI 在**同时满足**以下条件时启用（任一不满足则走对应分支，见 §6）：

| 条件 | 是否满足走离线 AI | 说明 |
|---|---|---|
| 防守方状态 | 离线（连续 >5min 无有效输入）/ 挂机（在线但无操作且未接管）/ 断线（心跳超时） | 引用经济 §3.3 离线判定 / PVP §3.6 断线 |
| 收到进攻 | 匹配系统下发 RaidCommand，目标进入防守态 | 引用 PVP §3.1 |
| 护盾状态 | **护盾未激活**（护盾生效则目标不可选，Raid 跳过） | 引用 PVP §3.3 / §5.3 |
| 波次状态 | 目标处于**和平窗口**（非 PVE 波次期） | PVP 仅和平窗口可攻（PVP §3.2）；若误撞 PVE 则目标获防御 DPS +20% 战时加成 |
| 新手保护 | 堡垒 **≥ Lv4** | Lv<4 关闭被进攻，不出现在候选列表（PVP §5.4） |
| 主动迎战 | 玩家未手动接管 DefendCommand | 若玩家在线并已操作 DefendCommand，则走在线防守，不走 AI |

> 触发时机图：`离线/断线` + `RaidCommand` + `¬护盾` + `和平窗口` + `Lv≥4` + `¬手动接管` → **离线 AI 托管**。否则：护盾→跳过；Lv<4→不可选；波次期→不可选（或误撞 +20%）；在线接管→DefendCommand。

### 3.2 Headless 模拟引擎（确定性 · 服务器权威）

离线 AI 不是独立战斗系统，而是**波次战斗内核的 headless 复用 + 进攻方 roster 注入**。模拟在服务端以固定 1s tick 运行（与经济 §3.1 / 能源 §3.1 同频），无客户端渲染。

**输入（LayoutSnapshot + RaidInput）：**
```
LayoutSnapshot {
  grid: cell -> { roomType, level, hp }      // 18×18 网格，坐标 (col,row)∈[0,17]×[0,17]（建造 §3.1）
  energyConfig: { rooms, modes }             // 能源房配置（普通/晶体催化，能源 §5.1）
  techBonuses: { T1-A, T1-B, T2-A, T2-B, T3-A, T3-B }  // 已解锁科技防守端加成（科技 §3.3，永久绑定档案）
  autoPriority: { roomId -> High|Normal|Low } // 玩家预设自动开火/修复优先级（复用 WaveCommand/DefendCommand 的 priority）
}
RaidInput {
  attackerRoster: [unit, ...]                // 进攻方单位（只读镜像，不可改布局，PVP §3.4）
  PS_atk, PS_def                             // 双方战力评分（PVP §5.1）
  K_ratio = clamp((PS_def/PS_atk)^0.5, 0.25, 1.0)   // 收益衰减（PVP §5.2 逐字）
  K_online = 0.10                            // 离线护盾外系数（PVP §5.5 逐字）
  seed                                       // 确定性种子 = hash(raidId, defenderId, startTick)
}
```

**模拟管线（与波次 §3.4 同源）：**
1. **初始化电网**：按能源 §3.1–§3.3 计算 `Supply/Demand`；赤字则按降载优先级 T4→T0（能源 §3.3/§5.4）shed，被 shed 的防御/武器 DPS 降至 **30%**（能源 §5.2/§5.5 逐字）。T0 指挥永不降载。
2. **应用科技防守加成**：T1-A 城墙承伤 HP ×(1+0.15×lv)；T2-A 武器/防御有效 DPS ×(1+0.08×lv)；T1-B 防御减速光环 +1 格；T3-B 来袭速度 ×(1−0.05×lv)（科技 §3.3/§5.2 逐字，全部防守端生效、进攻端无增益）。
3. **生成进攻单位**：从堡垒外缘战场环带（美术 §3.1，约 24–30 格见方）spawn，按 `attackerRoster` 注入（只读）。
4. **A\* 寻路 + 破墙（breach）**：服务端 A* 在 `(18×18 + 环带)` cell 网格运行（波次 §3.4 逐字）；城墙(1×1)/房间为障碍；无绕过路径则锁定最近阻挡 cell 攻击其 HP，HP 归零→breach（可通行缺口），继续向内推进。破墙 DPS 受单位类型影响。
5. **自动开火**：防御 Defense(3×3, HP 300) 范围拒止/减速（邻接城墙减速 +1 格）；武器 Turret(2×2, HP 160) 自动开火（波次 §3.4/§5.3 逐字）。按 `autoPriority` 选目标；DPS 受电网（满供或 30%）与科技加成调制；断能房恒 30% 保底（能源 §5.5）。
6. **攻防结算**：进攻单位攻击房间 HP（城墙 120 / 居住 100 / 生产 120 / 医疗 / 仓储 / 实验 3×3 / 指挥 600，波次 §5.3 逐字）；核心被触及→`coreHP` 下降。
7. **结束条件**：进攻单位全灭 / 超时（复用波次时间窗口逻辑）/ `coreHP` 归零 → 模拟终止，输出 `DefenseResult`。

**输出（DefenseResult）：**
```
DefenseResult {
  roomsDestroyed: [roomId, ...]   // 被毁房间（需修复）
  coreHP: int                     // 指挥核心剩余 HP（600 基准）
  defenseWin: bool                // 进攻方是否全灭（防守方守住）
  raidProgress: float ∈[0,1]      // 进攻方突入深度（核心被突破=1）
}
```

**确定性保证（防作弊 · 引用概念 R2）：**
- 所有随机性（目标 tiebreak、破墙锁定选择、单位 spawn 顺序、暴击）均取自 `seed` 驱动的确定性 PRNG；禁用心表/时钟/平台相关浮点不确定源。
- 固定 1s tick + 整数化中间量（伤害/HP 用定点或四舍五入固定规则），保证 PC/移动/Web 服务端重放 bit 一致。
- 模拟全程只读写服务端状态；客户端仅接收战报快照（与 PVP §3.1「客户端仅发输入」一致）。

### 3.3 与波次 / 能源 / 科技 / PVP 同源逻辑（逐字对齐清单）

| 维度 | 复用来源（逐字） | 离线 AI 中的处理 |
|---|---|---|
| 寻路/破墙 | 波次 §3.4 A* + breach | 同一份服务端 A* 内核；离线 PVE 与离线 PVP 共用 |
| 建筑承伤 HP | 波次 §5.3（城墙120/防御300/武器160/居住100/生产120/指挥600） | 直接复用，无离线专属 HP |
| 防御 3×3 / 武器 2×2 | 波次 §3.4 / §5.3 | 同尺寸、同自动开火逻辑 |
| 断电降级 | 能源 §5.2/§5.5（DPS 降至 30%） | 离线托管同样走电网稳态，断能房 30% 保底 |
| 降载优先级 | 能源 §3.3/§5.4（T4→T0） | 同 shed 顺序，T0 指挥永不降载 |
| 科技防守加成 | 科技 §3.3/§5.2（T1-A/T1-B/T2-A/T3-B 等） | 全部生效（防守端）；进攻端无科技（科技 §3.4） |
| 战力分桶 MMR | PVP §5.1（T1–T5，PS 公式，仅同桶/±1 桶匹配） | 匹配决定能否被选中；离线者按自身 PS_def 入桶 |
| 收益衰减 | PVP §5.2 `K_ratio=clamp((PS_def/PS_atk)^0.5,0.25,1.0)` | 逐字复用，不另起 |
| 掠夺公式 | PVP §5.5 `Loot_r=StoredDef_r×R_loot×K_ratio×K_online` | 逐字复用；离线 `K_online=0.10`，`R_loot=0.5` |
| 离线护盾 | PVP §5.3（每日1次8h/CD24h/护盾外≤5%） | 护盾生效→Raid 跳过、零损失；护盾外→K_online=0.10 封顶 5% |
| 出击成本 | PVP §5.5 / 经济 §5.3（废料 50 + 生物质 20） | 进攻方照常预缴，与在线一致 |
| 修复成本 | 波次 §5.5 / 建造 §3.3（原造价 ×0.5，α=0.5 对偶） | 离线被毁房间修复成本一致，不叠加额外惩罚 |
| 负值保护 | 经济 §6 `floor(Stored)=max(0,Stored−Loss)` | 资源损失永不为负，封顶 ≤5% |

### 3.4 战报（给防守方 · 对齐美术圣经视觉）

模拟结束结算后，向（重新上线的）防守方推送**离线战报**（OfflineBattleReport），视觉对齐美术圣经 §2.3/§7/§9：

| 战报项 | 内容 | 视觉锚点（美术圣经） |
|---|---|---|
| 来袭者 | 进攻方 ID、MMR 分桶（T1–T5）、PS_atk、K_ratio | 敌我以边框色+旗帜图标区分（美术 §7.3）：敌=暖橙 `DANGER_ORANGE #E8762E` |
| 战斗结果 | 守住 / 被突破（defenseWin + raidProgress） | 威胁色统一暖橙 + 图标/文字（非纯色，§9.1 色盲铁律） |
| 房间损毁 | 被毁房间清单 + 修复成本（原造价×0.5） | 受损叠加动态腐蚀贴片 §4.4（叙事废墟） |
| 损失资源 | 各资源 `Loot_r`（≤5% 封顶）逐资源列出 | 资源色：废料 `#8A8F9C`/晶体 `#48B6E8`/生物质 `#7E8856`（§2.7）+ 图标+数字（数据双通道 §7.1） |
| 护盾状态 | 是否处于护盾期（是→零损失标注） | 护盾色 `ENERGY_CYAN #48B6E8`（§4.2 护盾膜） |
| 可达性 | 对比度 ≥ WCAG 2.1 AA（§9.2）；色盲模拟开关可用 | 非色彩通道：图标+形状+文字（§9.1/§9.3） |

> 战报经「战斗回放」持久化（概念 §10.2 远期层观战/回放 + PVP §3.6 重连看回放），防作弊审计可重放本次 headless 模拟。

## 4. 玩家接口（三端统一抽象层 + OfflineDefenseCommand）

### 4.1 抽象动词（P5 低门槛高深度）
离线防御 AI 的「玩家侧」仅做**预设配置**（和平期设置，战斗期不可改，引用建造 §6 战斗锁定）；战斗由服务器 headless 自动运行。统一为 2 类预设指令，各端仅做输入翻译：

- **设自动优先级（SetAutoPriority）**：设定自动防御 AI 的集火/修复优先级（High/Normal/Low），离线托管与在线默认一致（复用 WaveCommand/DefendCommand 的 `priority` 字段）。
- **激活护盾（ActivateShield）**：手动激活每日 1 次离线护盾（8h，CD 24h）。

### 4.2 各端适配
| 端 | 输入方式 | 关键适配 |
|---|---|---|
| PC | 设置面板「自动防御预设」+ 护盾按钮（快捷键 S） | 高信息密度，预设优先级拖拽排序 |
| 移动 | 底部「防御预设」卡 + 护盾大按钮 | 触摸目标 ≥48dp（美术 §7.4）；护盾按钮防误触 |
| Web | 同 PC，限最大画布 | 禁用右键菜单冲突；键位与 PC 一致 |

### 4.3 统一指令结构（设计抽象，非实现代码）
```
OfflineDefenseCommand {
  type: SetAutoPriority | ActivateShield
  priority: High | Normal | Low   // 仅 SetAutoPriority 用（自动开火/修复顺序）
  shieldActivate: bool            // 仅 ActivateShield 用（每日1次/CD24h）
}
```
> 客户端**仅发送上述预设动词**；布局快照、模拟、电网、科技、掠夺结算全部以服务端为准（引用概念 R2）。OfflineDefenseCommand 与 RaidCommand / DefendCommand 并列，构成三端统一的对战指令抽象层（PVP §4.4）。

### 4.4 HUD 呈现（被攻通知 · 对齐美术 §7.3 三态）
- **离线期间被攻**：不弹实时 HUD（玩家不在场）；服务器静默运行 headless 模拟，战报留存待上线推送。
- **上线后战报**：以「防御态」视觉呈现——全屏边缘暖橙 `DANGER_ORANGE` 脉冲 vignette（美术 §7.3 波次预警同源）+ skull/盾牌图标 + 文字「离线期间遭突袭」+ 损失明细。
- **护盾倒计时**：运营态顶部显示护盾剩余时长（冷蓝 `ENERGY_CYAN`），与电力条同区（能源 §4.4）。

## 5. 关键数值

### 5.1 触发条件与护盾参数（逐字引用 PVP §5.3 / §5.4）
| 参数 | 值 | 来源 |
|---|---|---|
| 离线 AI 触发 | 离线/挂机/断线 + RaidCommand + ¬护盾 + 和平窗口 + Lv≥4 + ¬手动接管 | 本 §3.1 / PVP §3.3/§3.5 |
| 每日护盾激活次数 | 1 次 | PVP §5.3 |
| 免战时长 | 8h | PVP §5.3 |
| 冷却 CD | 24h（自激活起算） | PVP §5.3 |
| 护盾生效期损失 | 0（完全保护，Raid 跳过） | PVP §5.3 |
| 护盾外离线损失上限 | **≤5% 资源（按存量）** | PVP §5.3 / §5.5（由 `K_online=0.10` 落实） |
| 新手保护 | 堡垒 < Lv4 不可作为进攻目标 | PVP §5.4（Lv1–3 关闭被进攻） |

> **术语对齐声明**：概念 §10.2 与 PVP §5.3 的「护盾外 ≤5%」指**资源损失上限**（由 `K_online=0.10` 在掠夺公式 `Loot_r=StoredDef_r×0.5×K_ratio×0.10` 中体现，离线无护盾最大 `0.5×1.0×0.10=5%`），非「被进攻概率」。离线者仍可被选中进攻，但损失封顶 5%。

### 5.2 复用公式引用（逐字 · 严禁另起数值）
| 公式 | 表达式 | 来源 |
|---|---|---|
| 战力评分 PS | `PS = Σᵢ[BaseCV(roomTypeᵢ)×(1+0.5×(levelᵢ−1))] + TechBonus + 0.1×BlockedCells` | PVP §5.1 |
| 分桶匹配 | T1 0–600(Lv1–2) / T2 600–1800(Lv3) / T3 1800–4500(Lv4) / T4 4500–10000(Lv5) / T5 10000+(Lv6)；仅同桶/±1 桶 | PVP §5.1 |
| 收益衰减 | `K_ratio = clamp((PS_def/PS_atk)^0.5, 0.25, 1.0)` | PVP §5.2 |
| 掠夺公式 | `Loot_r = StoredDef_r × R_loot × K_ratio × K_online` | PVP §5.5 / 经济 §3.4 |
| 变量取值 | `R_loot`：在线=0.5 / 护盾=0；`K_online`：在线=1.0 / 离线护盾外=0.10 | PVP §5.5 |
| 出击成本 | 废料 50 + 生物质 20（发起即扣，不论胜负不退） | PVP §5.5 / 经济 §5.3 |

### 5.3 损毁 / 损失上限（逐字引用波次 §5.5 / 经济 §6）
| 项 | 数值 | 来源 |
|---|---|---|
| 资源损失上限 | `Loot_r ≤ StoredDef_r`；护盾外 ≤5%（`K_online=0.10`） | PVP §5.5 |
| 负值保护 | `floor(StoredDef_r)=max(0, StoredDef_r−Loot_r)` 永不为负 | 经济 §6 |
| 房间修复成本 | 原建造造价 × 0.5（α=0.5 对偶） | 波次 §5.5 / 建造 §3.3 |
| 建筑承伤 HP（Lv1） | 城墙120/防御300/武器160/居住100/生产120/指挥600 | 波次 §5.3 |
| 断电 DPS 保底 | 被 shed 防御/武器 DPS 降至 30% | 能源 §5.2/§5.5 |
| 软上限溢出 | 进攻方掠夺超自身软上限部分弃置 | 经济 §3.2 / PVP §5.5 |

### 5.4 离线 AI 与在线防守差异对照
| 维度 | 在线防守（DefendCommand） | 离线 AI（OfflineDefenseCommand） | 是否双重惩罚 |
|---|---|---|---|
| 手动微操 | 允许（集火/陷阱/优先级） | **不允许**（仅预设 `autoPriority`） | 否（差异仅为操作层） |
| 科技/电网效果 | 一致 | 一致（同源，不降罚） | 否 |
| 资源损失系数 | `K_online=1.0`（最高 50%） | `K_online=0.10`（封顶 5%） | 否（离线更宽松） |
| 房间修复成本 | 原造价 ×0.5 | 原造价 ×0.5 | 否（同源口径） |
| 护盾 | 同 | 同（护盾生效零损失） | 否 |

## 6. 边界与异常

| 场景 | 处理 |
|---|---|
| 模拟中途玩家上线（接管） | 服务器在下一个 1s tick 边界冻结当前 sim 状态，将控制权交还玩家转 DefendCommand 实时操作；**不重模拟、不撕裂**（引用 PVP §3.6 心跳判定上线时刻）。已发生的房间 HP/资源变更保留 |
| 布局快照与实时状态不一致 | 模拟**仅用服务端权威最新快照**（建造 §6 战斗锁定 + 服务端唯一真相）；客户端提交的离线快照若与 server 不符，直接拒绝并改用 server 状态（R2 防作弊兜底）。杜绝伪造布局 |
| 断线重连（防守方） | 服务器按冻结配置继续 headless 模拟至结算；重连看「战斗回放」；断开即判防守失败但**护盾仍生效**（护盾期零损失，PVP §3.6/§6）；不奖励断线逃避 |
| 新手保护 Lv<4 | 堡垒 <Lv4 不可作为进攻目标，不出现在候选列表；离线 AI 对其无触发可能（PVP §5.4） |
| 护盾激活期 | 目标不可选，Raid 请求服务端直接拒绝；零损失，不进入离线 AI（PVP §5.3） |
| 护盾 CD 中又遭进攻 | 护盾不可提前激活，只能等 CD；离线损失按 ≤5% 上限封顶（`K_online=0.10`） |
| 离线同时被 PVP + PVE | 时间分桶：PVP 仅和平窗口发起；若误撞 PVE 则目标获防御 DPS +20% 战时加成（PVP §3.7/§6）；同 tick 双倍消耗按服务端顺序串行结算（经济 §6 双倍冲突一致）；护盾仅免 PVP 不免 PVE |
| PVP 误撞 PVE 波次 | 进攻方排队或目标获防御 DPS +20% 战时加成；该加成在科技提升后的满值上叠加，断能房仍 30% 保底（能源 §3.6） |
| 核心被 PVP 进攻突破 | 模拟输出 `raidProgress=1`；资源按 `Loot_r` 结算（封顶 5% 离线）；核心 HP 受损。核心被 PVP 摧毁是否重置 Lv2 由 PVP GDD 战斗模型裁定（本系统不复写）；离线托管**不额外施加** Lv2 重置，避免离线双重惩罚（仅 PVE 波次核心被毁走重置 Lv2，概念 §9.3/波次 §5.5） |
| 模拟死锁 / 全封锁 | A* 带超时回退：无绕过路径强制锁定最近阻挡 cell 破墙；breach 后仍向内推进（波次 §6）；电网全断（Supply=0）仅 T0 指挥满供，防御全沉默（能源 §6） |
| 资源不足支付波次消耗（离线 PVE 叠加） | 弹药/应急不足仍按实际存量扣减（负值保护，经济 §6），缺口致对应武器塔该波降火力，不阻断进程 |

## 8. 设计风险与缓解

| # | 风险 | 严重度 | 具体缓解策略 |
|---|---|---|---|
| R20 | **确定性回放歧义 / 跨端浮点不一致**：headless 模拟若用未播种随机或平台相关浮点，重放结果漂移，战斗审计失效，R2 作弊兜底崩塌 | 高 | ① 全部随机取自 `seed=hash(raidId,defenderId,startTick)` 驱动 PRNG，禁用手表/时钟；② 固定 1s tick + 整数化中间量（伤害/HP 定点或定规四舍五入），保证服务端重放 bit 一致；③ 战报+模拟日志持久化，反作弊审计可重放（PVP §3.1/§3.6） |
| R21 | **离线 AI 弱于在线致不公平崩盘 / 或强于预期致离线零损**：无微操若差距过大→离线必败房间尽毁修复崩溃（违反"在线更安全"激励，概念 §2.3）；若 AI 过强→离线零损漏洞 | 中 | ① AI 与在线用**同一战斗内核**（寻路/破墙/开火/电网/科技同源），仅缺手动微操；② 预设 `autoPriority` = 在线默认优先级，不弱化处理；③ 资源层 `K_online=0.10` 封顶 5% 已宽松；④ 房间修复成本同源 0.5×造价，不搞离线额外惩罚（§5.4 对照表） |
| R22 | **快照不一致 / 过期布局被利用**：离线期间玩家短暂上线改布局或客户端伪造布局快照→模拟用错布局，引发不公平或作弊 | 中 | ① 模拟**永远用服务端权威最新快照**（建造 §6 锁定 + 服务端唯一真相）；② 客户端离线快照仅缓存，提交与 server 不符直接拒绝（R2 兜底）；③ 战斗锁定保证模拟期布局不可变，快照稳定 |
| R23 | **上线接管时机竞态 / 战斗撕裂**：模拟中途玩家上线，控制权交接若不在 tick 边界→状态撕裂或重复模拟，结算混乱 | 中 | ① 接管严格在 1s tick 边界发生，冻结当前 sim 状态转交 DefendCommand（PVP §3.6 心跳判上线）；② 不重演已模拟 tick，已发生 HP/资源变更保留；③ 重连看回放验证一致性 |
| R24 | **离线 PVP 与 PVE 双线叠加致双重惩罚/豁免**：离线时同时被 PVP 突袭 + PVE 波次，双倍消耗/损毁被误判为双重惩罚，或护盾误免 PVE | 中 | ① 时间分桶：PVP 仅和平窗口发起（PVP §3.2）；② 误撞给目标防御 DPS +20% 战时加成优先保 PVE（PVP §3.7）；③ 同 tick 双倍消耗按服务端串行结算 + 负值保护（经济 §6）；④ 护盾**仅免 PVP 不免 PVE**（PVP §5.3），杜绝双重豁免 |

> 红线追踪：本系统以「战斗内核同源（波次/在线/科技/电网）+ 掠夺公式逐字复用（PVP §5.5）+ `K_online=0.10` 封顶 5% + 修复成本同源 0.5×造价」四重机制，规避**双重惩罚/双重豁免**与 R6 经济失衡（掠夺超软上限弃置），并以确定性 PRNG + 服务端快照权威对冲 **R2 作弊**（R20/R22）；R21/R23/R24 为离线 AI 自身风险（编号接续科技 R19），分别兜底「离线强弱失衡」「接管竞态」「双线叠加」，无设计红线遗漏。
