# 实时 PVP 对战系统 GDD（Game Design Document）

> 阶段：Phase 2 系统设计（第二个系统 · 用户最关注差异点）
> 服务支柱：P4 实时对抗的快感（Thrill of Real-time Conflict）
> 对应核心动词：Raid（出征）
> 依赖系统：建造系统（布局锁定）/ 波次系统（和平窗口判定）/ 匹配系统（MMR）
> 文档负责人：design-strategist（由 design-strategist-pvp 落盘）
> 备注：本系统为延伸层（Extended）上线必需；概念阶段四大红线（主导策略/经济失衡/认知过载/支柱漂移）中，本系统主要对冲 R1（高战力碾压新手）与 R2（作弊），其余红线由关联系统兜底。

---

## 1. 系统概述

实时 PVP 对战系统让**已达 Lv4 的玩家在和平窗口实时突袭他人堡垒**：进攻方手动派遣、操控单位、瘫痪关键房间并战后掠夺，防守方（在线反击 / 离线 AI 托管）守护资源——所有状态以服务端为准，是「实时对抗的快感」（P4）支柱的承载核心，也是区别于纯塔防 / 纯经营的关键玩法差异点。

一句话定义：**实时 PVP 对战系统 = 把"出征(Raid)"从异步点击升级为服务器权威、可博弈、强反馈的实时对抗**。

---

## 2. 设计目标与验收标准

### 2.1 设计目标
- G1 实时权威对抗：状态全服务端，客户端仅发输入，杜绝穿墙/加速/改资源（引用概念 R2）
- G2 公平匹配：战力分桶（MMR-like），越级不可匹配，缓解高战力碾压新手（引用概念 R1）
- G3 收益防碾压：打弱目标收益衰减，使"刷新手"无利可图（R1）
- G4 离线安心：每日 1 次 8h 护盾 + 护盾外损失 ≤5%，杜绝"睡觉被搬空"
- G5 新手保护：堡垒 < Lv4 关闭被进攻，平滑引入对抗（R1 + R3）
- G6 双威胁解耦：仅和平窗口可进攻 + 战时加成，PVP 与 PVE 互不挤占（P2 / R3）
- G7 三端一致：PC / 移动 / Web 共用同一套 RaidCommand / DefendCommand 抽象（P5）

### 2.2 验收标准（延伸层门控）
| 编号 | 验收项 | 通过条件 |
|---|---|---|
| AC1 | 服务器权威 | 所有布局/资源/单位状态以服务端为准；客户端篡改布局/资源不生效 |
| AC2 | 和平窗口约束 | 目标处于 PVE 波次期时不可发起进攻；误撞给战时加成 |
| AC3 | 护盾生效 | 护盾期内目标不可被选；护盾外离线损失 ≤5% 实测达标 |
| AC4 | 分桶匹配 | 仅同桶 / 相邻 ±1 桶可匹配；跨 2 桶以上返回空列表 |
| AC5 | 收益衰减 | 进攻方 PS ≥ 防守方 4× 时，K_ratio ≤ 0.5 实测生效 |
| AC6 | 新手保护 | Lv1–3 堡垒不出现在任何进攻候选列表中 |
| AC7 | 断线结算 | 任一方断线，服务器模拟至结算；重连可看回放；不奖励逃跑 |
| AC8 | 三端一致 | PC / 移动 / Web 同一 RaidCommand 在服务端结果完全一致 |

## 3. 核心机制

### 3.1 服务器权威架构（概念 §10.2 · R2）
- **唯一真相源**：堡垒布局、房间状态、单位位置/血量、资源计数、护盾状态全部存于服务端。
- **客户端仅发输入**：客户端只发送动词指令（RaidCommand / DefendCommand），不发送任何状态；服务端按固定 tick 模拟并广播快照。
- **预测与校正**：客户端可做本地视觉预测（如单位移动插值）提升手感，但服务端权威校正任何不一致——命中/伤害/资源变更只认服务端结果。
- **反作弊兜底**：心跳保活 + 战斗回放审计；异常（加速、无限资源、越界路径）直接判违规并回滚（缓解 R2）。
- **只读对方布局**：进攻方加载的是防守方布局的"只读镜像"，任何改布局指令服务端拒绝（能力边界见 §3.4）。

### 3.2 和平窗口才可进攻（概念 §10.4）
- PVP 突袭为**实时事件**，但**仅可在目标"非波次期（和平窗口）"发起**。
- 发起前，匹配系统向波次系统查询目标状态：
  - 目标处于 PVE 波次期 → 不可选；HUD 显示"目标迎战中"。
  - 目标处于和平窗口 → 可发起；进攻方进入"反攻态"（HUD 见 §4.3）。
- 设计意图：PVE 体验优先，避免"刚被打丧尸又被人抄家"的双重惩罚（P2 / R3）。

### 3.3 离线护盾（概念 §10.2）
- **机制**：玩家可手动激活**每日 1 次免战护盾**，时长 8h；护盾生效期间不可被进攻、零损失。
- **兜底**：若玩家离线且护盾未激活（或已过期），被攻时由自动防御 AI 托管，且损失封顶 ≤5% 资源（杜绝清零式搬空）。
- **CD 约束**：护盾 CD 24h（自激活起算），不可提前续接，保证每天至多 1 次且天然覆盖夜间睡眠。
- 详见 §5.3 数值表。

### 3.4 进攻方能力边界（概念 §10.1）
| 能做什么 | 不能做什么 |
|---|---|
| 实时派遣单位进入对方网格 | 不能直接改对方布局（只读镜像） |
| 手动操控走位 / 集火 / 指定目标 | 不能穿墙瞬移（路径服务端校验） |
| 瘫痪能源或防御房间以削弱（限机制内，如断电降级） | 不能离线强攻（护盾期内不可选） |
| 战后按结算公式掠夺资源 | 不能反向控制防守方单位 / 不能临时改建 |

### 3.5 防守方能力边界（概念 §10.1）
**在线防守方**
- 能：手动操作防御武器反击；激活陷阱 / 技能；实时看到进攻单位并切换应对；调度自动防御优先级。
- 不能：反向控制进攻方单位；战斗中临时改建（布局锁定，引用建造系统 §6）。

**离线 / 断线防守方**
- 能：堡垒由"自动防御 AI"托管（预设武器自动开火、城墙阻挡、陷阱按预设触发）。
- 不能：手动微操；护盾 CD 内仅损失少量资源（≤5%）。

### 3.6 断线处理（概念 §10.2）
- **服务器继续模拟**：任一方断线，服务端按最后有效指令 + 托管 AI 继续推进至战斗结束并结算，不暂停全局。
- **重连看回放**：断线方重连后可观看"战斗回放"（引用概念远期层观战/回放）。
- **不奖励逃跑**：
  - 进攻方断线 → 视为进攻失败，单位撤退，无缴获；结算照常；出击成本按经济系统 §5.3 预缴不退。
  - 防守方断线 → 堡垒切自动防御 AI 托管；断开即判防守失败，但**护盾仍生效**（若处于护盾期则零损失）。
- 心跳超时即判负，杜绝"拔线保资源"博弈。

### 3.7 PVP 与 PVE 共存（概念 §10.4）
- **时间分桶**：PVE 波次为固定周期（90s，见概念 §9）；PVP 突袭为实时事件，但仅可在对方和平窗口发起（§3.2）。
- **战时加成**：若进攻方发起时目标"恰入"PVE 波次（边界场景见 §6），目标获**防御 DPS +20%** 战时加成，优先保障 PVE 体验。
- **双线模式（可选）**：仅双方均在线且主动开启时，HUD 分区显示两路、服务端并行模拟、结果独立结算；非默认高玩模式（§6）。
- **结论**：通过"和平窗口才可进攻 + 战时加成"，PVP 与 PVE 在时间与规则上解耦，互不挤占（规避 P2 疲劳与 R3 认知过载）。

## 4. 玩家接口（三端统一抽象层）

### 4.1 抽象动词（P5 低门槛高深度）
统一为 2 类对战指令，各端仅做输入翻译：
- **进攻指令（Raid）**：派遣 / 移动 / 集火 / 瘫痪（针对能源或防御房间）。
- **防守指令（Defend）**：反击 / 陷阱激活 / 防御优先级调度。

### 4.2 各端适配
| 端 | 输入方式 | 关键适配 |
|---|---|---|
| PC | 鼠标框选单位 + 右键移动/集火 + 快捷键（T 陷阱 / F 集火） | 高信息密度，小地图 + 单位血条 |
| 移动 | 底部单位栏拖拽出击 + 点选目标 + 长按弹指令 | 触摸目标 ≥48dp；自动寻路防误操作 |
| Web | 同 PC，限最大画布 | 禁用右键菜单冲突；键位与 PC 一致 |

### 4.3 HUD 三态区分（概念 §10.3 · P5 防认知过载）
| 状态 | 触发 | HUD 表现 |
|---|---|---|
| 运营态 | 和平窗口、无对战 | 资源条 / 建造坞 / 波次倒计时为主 |
| 防御态 | 被 PVP 进攻（或被 PVE 波次） | 暖橙警报框（⚠ 图标）+ 防守指令栏 + 单位/房间血条高亮 |
| 反攻态 | 本方发起 PVP | 进攻小地图 + 派遣栏 + 掠夺进度条 |
> 三态互斥切换，避免同时暴露过多决策项（R3 认知过载兜底）。
> **视觉一致性声明**：防御态告警框统一用暖橙（DANGER_ORANGE #E8762E）+ ⚠ 图标，不引入第二层红色警报框，遵循《美术圣经》§2.3 单层暖橙铁律。

### 4.4 统一指令结构（设计抽象，非实现代码）
所有端输入归一为：
```
RaidCommand {
  type: Dispatch|Move|FocusFire|Disable
  unitIds: [id, ...]          // 派遣/操控的单位
  target: cell|(roomId)        // 目标格或房间（Disable 用）
}
DefendCommand {
  type: CounterFire|Trap|SetPriority
  target: cell|(roomId)
  priority: High|Normal|Low    // 自动防御 AI 优先级（离线托管用）
}
```
> 客户端**仅发送上述动词指令**；所有校验、路径合法性、伤害结算以服务端为准（R2）。

## 5. 关键数值

### 5.1 战力分桶 MMR 匹配规则
**战力评分（PS）公式**（由匹配系统计算，权重待平衡 pass 复核）：
`PS = Σᵢ [ BaseCV(roomTypeᵢ) × (1 + 0.5×(levelᵢ−1)) ] + TechBonus + 0.1×BlockedCells`
- `BaseCV(roomType)`：房间基础作战值（下表，单位：战力点）
- `levelᵢ`：房间等级（1–5）
- `TechBonus`：科技树提供的战力加成（估算 0–2000）
- `BlockedCells`：城墙/防御占据的阻挡格数（奖励布局防御）

**房间基础作战值 BaseCV：**
| 房间类型 | BaseCV |
|---|---|
| 指挥 Command | 100 |
| 防御 Defense | 60 |
| 武器 Turret | 45 |
| 实验 Lab | 25 |
| 医疗 Medical | 20 |
| 能源 Energy | 15 |
| 生产 Production | 8 |
| 居住 Housing | 5 |
| 仓储 Storage | 5 |
| 城墙 Wall | 3 / cell |

**分桶与匹配：**
| 分桶 | PS 范围 | 对应堡垒等级 | 匹配范围 |
|---|---|---|---|
| T1 | 0–600 | Lv1–2 | 仅 T1 |
| T2 | 600–1800 | Lv3 | T1–T3 |
| T3 | 1800–4500 | Lv4 | T2–T4 |
| T4 | 4500–10000 | Lv5 | T3–T5 |
| T5 | 10000+ | Lv6 | T4–T5 |

> 匹配系统仅返回**同桶或相邻 ±1 桶**候选目标，按（在线状态 → 可掠夺资源量 → 距离）排序；跨 2 桶以上返回空列表，**彻底杜绝 T5 碾压 T1（缓解 R1）**。

### 5.2 进攻收益衰减（防碾压 · R1）
`K_ratio = clamp( (PS_def / PS_atk)^0.5 , 0.25 , 1.0 )`
| PS_atk / PS_def 比值 | K_ratio | 说明 |
|---|---|---|
| ≤1.0 | 1.00 | 公平对战，全额收益 |
| 2× | 0.71 | 略降 |
| 4× | 0.50 | 收益减半 |
| 8× | 0.35 | 强碾弱，收益大降 |
| ≥16× | 0.25（下限） | 严重越级，仅 25% 收益 |

> 配合分桶匹配，使"专挑弱目标刷资源"无利可图（R1 核心缓解）。

### 5.3 离线护盾 CD 与免战时长
| 参数 | 值 |
|---|---|
| 每日激活次数 | 1 次 |
| 免战时长 | 8h |
| 冷却 CD | 24h（自激活起算） |
| 护盾生效期损失 | 0（完全保护） |
| 护盾外离线损失上限 | ≤5% 资源（按存量） |

### 5.4 新手保护（<Lv4 关闭被进攻 · R1 / R3）
| 条件 | 处理 |
|---|---|
| 堡垒 < Lv4（Lv1–3） | 不可作为进攻目标（关闭被进攻）；不出现在任何候选列表 |
| 堡垒 ≥ Lv4 | 解锁 PVP 出征，且可被进攻 |

> 与概念 §8 生长曲线一致：Lv4 为"首次突袭他人堡垒"里程碑。

### 5.5 掠夺结算公式
`Loot_r = StoredDef_r × R_loot × K_ratio × K_online`
| 变量 | 含义 | 单位 | 取值 |
|---|---|---|---|
| `Loot_r` | 进攻方掠夺到的资源 r 总量 | 资源单位 | 输出 |
| `StoredDef_r` | 防守方资源 r 存量 | 资源单位 | 实时读取 |
| `R_loot` | 基础掠夺比例 | 比例 | 在线实战 = 0.50；护盾生效 = 0 |
| `K_ratio` | 收益衰减系数 | 比例 | ∈[0.25,1]（查 §5.2） |
| `K_online` | 防守方在线系数 | 比例 | 在线 = 1.0；离线护盾外 = 0.10 |

**上限约束**：`Loot_r ≤ StoredDef_r`；且进攻方资源不超软上限（超出部分弃置，引用经济系统 R6 防通胀）。

**进攻方出击成本（单一真相源归经济系统 GDD §5.3）**：每次发起 PVP 需预缴 废料 50 + 生物质 20，发起即扣、不论胜负不退（与 §3.6「断开判进攻失败无缴获」一致，防免费试探）。本系统不独立建模进攻方消耗，避免与经济系统双源漂移。

**示例**：
- 在线防守、公平匹配（K_ratio=1.0）：`Loot = Stored × 0.5 × 1.0 × 1.0 = 50%` 被掠。
- 越级 4×（K_ratio=0.5）：`Loot = Stored × 0.5 × 0.5 × 1.0 = 25%`。
- 离线无护盾（K_online=0.10）：`Loot = Stored × 0.5 × 1.0 × 0.10 = 5%`（与概念 §10.2 护盾外 ≤5% 一致）。
- 护盾生效：`R_loot = 0` → 零损失。

## 6. 边界与异常

| 场景 | 处理 |
|---|---|
| 双方均在线双线模式 | HUD 分区显示两路；服务端并行模拟；结果独立结算；非默认，需双方主动开启（概念 §10.4） |
| 目标恰入 PVE 波次 | 进攻方进入排队，或目标获**防御 DPS +20%** 战时加成；优先保障 PVE 体验，避免双重惩罚 |
| 护盾期内不可攻 | 护盾生效时目标不可被选为进攻目标，HUD 显示"受保护"；发起请求服务端直接拒绝 |
| 网络分区（进攻方断线） | 服务端继续模拟至结算；进攻方单位超时撤退；重连看回放；断开判进攻失败、无缴获 |
| 网络分区（防守方断线） | 堡垒切自动防御 AI 托管；断开判防守失败，但**护盾仍生效**（护盾期零损失）；重连看回放 |
| 强退避免惩罚 | 心跳超时即判负，不奖励"拔线保资源" |
| 双方同时进攻对方 | 各自独立发起，互不冲突；双方都进入被攻态，各自防守各自 |
| 护盾 CD 中又遭进攻 | 护盾不可提前激活，只能等 CD；离线损失按 ≤5% 上限封顶 |
| 进攻中防守方升级堡垒 | 战斗中布局锁定（建造系统 §6），升级指令排队至战斗结束 |
| 资源软上限溢出 | 掠夺超出进攻方软上限部分弃置，不进入经济循环（R6） |

## 7. 依赖系统

| 依赖系统 | 对本系统的影响 |
|---|---|
| 建造系统 | 战斗中本方布局锁定（§6）；进攻方加载防守方布局只读镜像；房间尺寸/朝向影响进攻路径与射界 |
| 波次系统 | 判定目标是否处于 PVE 波次期（和平窗口），决定可否进攻及是否触发战时加成（§3.2 / §6） |
| 匹配系统（MMR） | 提供战力评分 PS、分桶与候选目标列表（§5.1）；实现公平匹配以缓解 R1 |
| 经济系统 | 掠夺结算的资源类型（废料/晶体/生物质）、软上限与溢出弃置（§5.5，R6） |
| 离线防御 AI | 防守方离线/断线时的自动托管逻辑来源（§3.5 / §3.6） |

## 8. 设计风险与缓解

| # | 风险（引用概念 §12） | 严重度 | 具体缓解数值 / 策略 |
|---|---|---|---|
| R1 | **实时 PVP 平衡**：高战力碾压新手，劝退 | 高 | ① 战力分桶匹配：仅同桶/±1 桶可匹配，跨 2 桶返回空列表（§5.1）；② 收益衰减：PS_atk≥PS_def×4 时 K_ratio≤0.5，下限 0.25（§5.2）；③ 新手保护：Lv<4 关闭被进攻（§5.4）；④ 离线护盾：每日 1 次 8h + 护盾外 ≤5%（§5.3）。四重叠加，使越级farm收益趋近于零 |
| R2 | **作弊 / 服务器权威**：客户端篡改（加速、无限资源、穿墙） | 高 | ① 全状态服务端权威，客户端仅发 RaidCommand/DefendCommand 动词（§3.1/§4.4）；② 路径服务端校验，穿墙瞬移拒绝（§3.4）；③ 资源/伤害服务端重算；④ 心跳保活 + 战斗回放审计，异常回滚（§3.1/§3.6） |
| R3 | **双威胁认知过载**：PVE+PVP 并行 overwhelmed | 中 | ① 时间分桶（仅和平窗口可攻）+ HUD 三态互斥（§4.3）；② 误撞给战时加成优先保 PVE（§3.7/§6）；③ 新手期关 PVP（§5.4） |
| R6 | **经济失衡**：掠夺致资源通胀 | 中 | ① 基础掠夺比例限 50% 且受 K_ratio 衰减（§5.2/§5.5）；② 进攻方软上限溢出弃置（§5.5）；③ 护盾外离线仅 5%，限制被动吸血 |
