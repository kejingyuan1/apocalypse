# 社交/联盟系统 GDD（Game Design Document）

> 阶段：Phase 2 系统设计（第八个系统 · 远期层 · 长期留存与 PVP 社会层支撑）
> 服务支柱：P4 实时对抗的快感（Thrill of Real-time Conflict）｜ 协同 P3 看得见的成长
> 对应核心动词：社交（Socialize，概念 §2.4 Fellowship / §4 Socializer / §13）
> 依赖系统：实时 PVP 对战系统（MMR/收益衰减/护盾/RaidCommand）/ 经济系统（资源不共享红线/软上限/负值保护）/ 离线防御 AI（headless 模拟/护盾/双线叠加）/ 建造系统（布局锁定）/ 美术圣经（UI/色盲友好/WCAG AA）
> 文档负责人：design-strategist（文策渊）
> 备注：本系统为远期层（概念 §6.3 ·「社交：联盟/好友、基地互访、排行榜（基础）」扩展）。它是长期留存与 PVP 社会层（LeBlanc Fellowship）的承载，必须与经济系统「资源不跨账号共享」红线一致，不可成为资源转移通道（防 R6 通胀）。承接《游戏概念文档》§2.4/§4/§6.3/§12、《实时 PVP 对战系统 GDD》《经济系统 GDD》《离线防御 AI GDD》《美术圣经》。

## 1. 系统概述

社交/联盟系统管理 **好友（Friend）/ 联盟（Alliance）/ 协同进攻（Rally Raid）/ 情报共享（Intel）/ 沟通层（Chat & Report）**，是「实时对抗的快感」（P4）与「社群（Fellowship）」美学维度的承载核心——它把单人突袭升级为有组织的联盟战争，提供长期留存的社交钩子（概念 §4 Socializer），并成为 PVP 的"社会层"（谁和谁结盟、谁抄了谁的家的战报成为社交货币，概念 §3.1 Relatedness）。

一句话定义：**社交/联盟系统 = 在服务器权威、资源不跨账号共享的硬约束下，把"出征(Raid)"从个人行为升级为联盟协同（集结进攻/情报共享/战报叙事），且绝不提供任何可掠夺的三资源转移通道（防 R6 通胀）。**

> **与经济红线的铁律（本系统最高优先级）**：经济系统 GDD §3.2/§3.4 已确立「**资源不跨账号共享**」红线（废料/晶体/生物质 仅归属单个账号，软上限 SoftCap_r 与负值保护均以单账号为边界，防 R6 通胀）。本系统所有机制（好友/联盟/仓库/增援/战利品分摊）**不得**让三类资源在账号间直接转移或绕过软上限。任何"联盟仓库"若存储三资源即视为违反红线，须否决或改为非交易性令牌（见 §3.4）。

## 2. 设计目标与验收标准

### 2.1 设计目标
- G1 社交留存：好友/联盟/聊天/战报提供长期留存钩子，服务概念 §3.1 Relatedness 与 §4 Socializer（P4 / Fellowship）
- G2 联盟协同进攻：集结 Rally Raid 让成员对同一目标联合出兵，与 PVP 的 RaidCommand / MMR 分桶 / 收益衰减 / 护盾 严格协同（引用 PVP §3 / §5）
- G3 情报共享不破坏 PVP 公平：友方摘要可见、敌方仅外部侦查摘要（不泄露完整布局），对齐 PVP 信息不对等（引用 PVP §3.4 只读镜像哲学）
- G4 经济红线不可破：严禁三资源跨账号转账/援助；不提供可掠夺共享仓库；任何联盟令牌不可兑换回三资源、不可被掠夺（R6 防通胀）
- G5 离线防御社会层：联盟通过情报预警/反击集结/可选非掠夺增援参与他人离线被攻，但不直接操控他人堡垒（与离线 headless 模型 + 账户隔离一致，引用离线 §1/§3）
- G6 三端一致：PC / 移动 / Web 共用同一套 SocialCommand / AllianceCommand 抽象（P5 低门槛高深度，引用 PVP §4.4）
- G7 沟通安全：联盟聊天/私聊/战报对齐美术圣经色盲友好与 WCAG AA；垃圾信息/举报有兜底

### 2.2 验收标准（远期层门控）
| 编号 | 验收项 | 通过条件 |
|---|---|---|
| AC1 | 关系模型完整 | 好友双向、联盟层级（盟主/副盟主/成员）、申请/邀请/踢出/退出/解散流程均可走通且服务端权威 |
| AC2 | 集结只结算一次 | 同一 Rally 对同一目标仅触发一次合并模拟、一次掠夺结算；多人不各自模拟、不各自全量掠夺（引用 PVP §5.5） |
| AC3 | 集结分桶约束 | 所有 Rally 参与者须满足 PVP §5.1 分桶约束（同桶/±1 桶）方可加入；越界成员服务端拒绝加入 |
| AC4 | 收益分摊正确 | 总掠夺 Loot_total_r 按各成员 PS 贡献占比分摊入账，各自受自身软上限封顶、溢出弃置（引用经济 §3.2/§3.4） |
| AC5 | 情报不泄露布局 | 敌方侦查仅返回外部摘要字段（§5.4），不返回房间类型/坐标/精确资源；友方摘要不进入 PVP 互攻（友好 fire 关闭） |
| AC6 | 经济红线不可破 | 无任何接口可将三资源在账号间转移；联盟令牌不可兑换三资源、不可被掠夺；审计可查（R6） |
| AC7 | 护盾/和平窗口协同 | 集结发起/加入时目标须处非护盾+和平窗口（引用 PVP §3.2/§3.3）；护盾生效或服务端拒绝 |
| AC8 | 退盟在途处理 | 成员退盟时其进行中 Rally 贡献按 §6 处理，已结算战利品不受影响、未结算份额取消且出击成本不退（引用 PVP §5.5） |
| AC9 | 三端一致 | PC / 移动 / Web 同一 SocialCommand/AllianceCommand 在服务端结果完全一致 |
| AC10 | 色盲/可达性 | 聊天/战报/情报 UI 满足美术圣经 §9 WCAG AA + 图标+形状+文字非色彩通道 |

## 3. 核心机制

### 3.1 关系模型（好友 / 联盟 / 流程）

**好友（Friend）**
- 双向 1-1 关系，需双方确认；上限 **50** 人（见 §5.1）。
- 权益：互相可见堡垒摘要（同友方摘要，见 §5.4）、可发起私聊、可"基地互访"（只读镜像参观，引用 PVP §3.4 只读哲学）、可互相侦查（因友好，可见完整布局，但不互攻）。
- **红线**：好友间不可转账三资源（G4）；好友关系不构成 PVP 目标豁免（仍可互相 Raid，除非同联盟）。

**联盟（Alliance）层级**
- 三级：盟主（Leader，1 人）/ 副盟主（Co-Leader，0–3 人）/ 成员（Member，其余）。
- 规模上限 **30** 人（见 §5.1）；超出须踢人或拆分。
- 权限矩阵：

| 操作 | 盟主 | 副盟主 | 成员 |
|---|---|---|---|
| 审批申请 / 发邀请 | ✓ | ✓ | ✗ |
| 踢出成员（非盟主） | ✓ | ✓ | ✗ |
| 任命/罢免副盟主 | ✓ | ✗ | ✗ |
| 发起/取消集结 Rally | ✓ | ✓ | ✓（自建） |
| 设置自动增援/情报共享 | ✓ | ✓ | 仅自身 |
| 解散联盟 | ✓（需确认） | ✗ | ✗ |
| 退出联盟 | ✓（先转移盟主） | ✓ | ✓ |

**申请 / 邀请 / 踢出 / 退出 / 解散流程**
- **申请（Apply）**：玩家向联盟提交申请 → 盟主/副盟主审批；联盟可设自动审批（等级/MMR 门槛）。
- **邀请（Invite）**：盟主/副盟主邀请 → 玩家接受；被邀者不受好友限制。
- **踢出（Kick）**：盟主/副盟主踢成员（不可踢盟主/其他副盟主），有 **30s 冷却**防滥用；被踢者 24h 内不可重新申请同一联盟。
- **退出（Leave）**：成员随时退出；若盟主退出须先转让或解散（否则系统自动转让予最早加入副盟主，无副盟主则解散）。
- **解散（Disband）**：盟主二次确认解散；成员回到无联盟态，进行中 Rally 按 §6 处理。
- **友好 fire 规则**：联盟内成员**禁止互攻**（RaidCommand 对同联盟目标服务端拒绝），故内部情报共享不破坏 PVP 公平（G3）。跨联盟/无联盟玩家之间正常 PVP。

### 3.2 协同进攻（Rally Raid）— 与 PVP 严格协同

Rally Raid 是多名联盟成员对**同一目标**发起的**集结联合进攻**。设计原则：**多人不各自模拟、目标只结算一次、总掠夺受 K_ratio 衰减、战利品按贡献分摊**。

**集结生命周期**
1. **发起（StartRally）**：盟主/副盟主/成员对目标发起，服务端校验：
   - 目标须 **≥ Lv4**（新手保护，PVP §5.4）；
   - 目标须处**非护盾 + 和平窗口**（引用 PVP §3.2/§3.3；护盾生效则拒绝，误撞 PVE 给目标防御 DPS +20% 战时加成，引用 PVP §3.7）；
   - 发起者须满足 PVP §5.1 分桶约束（同桶/±1 桶），否则拒绝。
   - 创建 Rally 会话（rallyId），开启**集结准备窗口 300s**（见 §5.2）。
2. **加入（JoinRally）**：其他成员在窗口内携单位加入，服务端二次校验**每位加入者**的分桶约束（同桶/±1 桶，PVP §5.1）——越界者拒绝加入（AC3）。每位加入者**各自预缴出击成本 废料 50 + 生物质 20**（与单人 Raid 一致，引用 PVP §5.5/经济 §5.3，发起即扣不论胜负不退）。
3. **发起结算（窗口满员或 300s 到）**：服务端合并所有参与者单位为**一次**模拟，对目标**仅结算一次**。
4. **分摊入账**：按各成员 PS 贡献占比分摊总掠夺，各自受自身软上限封顶、溢出弃置（引用经济 §3.2/§3.4）。

**是否多人同时模拟？→ 否。** 多进攻者**不各自独立模拟**（否则同一目标会被多次掠夺，5 人各掠 50% = 250% 通胀漏洞）。改为：**合并 roster → 单次 headless/在线模拟 → 一次结算 → 按贡献分摊**。无论防守方在线（单次 DefendCommand 对合并 roster）或离线（单次 headless 模拟对合并 roster，引用离线 §3.2），均为一次战斗。

**目标只结算一次（防通胀核心）**：总掠夺公式复用 PVP §5.5，仅将 PS_atk 替换为合并战力：
`Loot_total_r = StoredDef_r × R_loot × K_ratio_rally × K_online`
- `K_ratio_rally = clamp( (PS_def / PS_atk_combined)^0.5 , 0.25 , 1.0 )`，`PS_atk_combined = Σ PS_atk_i`（逐字复用 PVP §5.2）
- `R_loot`：在线=0.50 / 护盾=0（护盾生效不会进入 Rally，故实际=0.50）
- `K_online`：在线=1.0 / 离线护盾外=0.10（逐字复用 PVP §5.5）
- 上限：`Loot_total_r ≤ StoredDef_r`；各成员份额 `Loot_i_r = Loot_total_r × (PS_atk_i / PS_atk_combined)` 再受各自 SoftCap_r 封顶、溢出弃置

**收益分摊与通胀对冲**（与单人 Raid 对比见 §5.3 示例）：合并 PS 越高 → K_ratio 越低（下限 0.25）→ 总掠夺越小，且目标仅结算一次，彻底杜绝"多人各自全量掠夺"。集结的战术价值在于**攻克单人打不过的强目标 / 降低个人风险**，而非刷资源（R25 缓解）。

### 3.3 情报共享（Intel）— 对齐 PVP 信息不对等

**友方摘要（联盟/好友内部，安全可见）**
- 联盟成员互相可见彼此堡垒摘要（§5.4 左列字段），含 PS、MMR 分桶、在线/离线、护盾状态、资源存量（banded：低/中/高）、上次活跃。
- 因**友好 fire 关闭**（§3.1），内部互看不进入 PVP，不构成信息不对等破坏，安全。
- 友方/好友可"基地互访"只读参观（含完整布局，引用 PVP §3.4 只读镜像）。

**敌方外部侦查（Scout，仅外部摘要，不泄露布局）**
- 对任意非友方目标执行侦查（Scout），返回**仅外部摘要**（§5.4 右列），**不返回房间类型/坐标/精确资源/能源配置**——保留 PVP 信息不对等（引用 PVP §3.4「进攻方加载只读镜像、不暴露完整布局」哲学，对齐 PVP 公平）。
- 成本与冷却：每次侦查消耗 **生物质 10**，同一目标 **CD 3600s（1h）**（见 §5.5），防侦查 spam。
- 侦查结果可上链至**联盟情报板**共享（仍仅外部摘要），供集结选目标参考。

**对齐 PVP 公平要点**：完整布局（18×18 网格、房间占位、能源网、科技加成）**仅在该玩家实际发起 RaidCommand 后由服务端只读下发**（PVP §3.1/§3.4）。社交层绝不前置泄露，避免"先看布局再决定打不打"破坏实时对抗快感（P4）与信息不对等。

### 3.4 联盟仓库红线（经济 R6 防通胀铁律）

**严禁项（服务端强制）**
- 禁止三资源（废料/晶体/生物质）在任意账号间通过联盟/好友接口直接转账、赠送、援助（违反经济 §3.2 资源不跨账号共享红线）。
- 禁止提供"可掠夺共享仓库"——即联盟仓库若存三资源，既绕过单账号软上限又成为掠夺/转移通道，直接否决。

**可选：非交易性联盟令牌（Alliance Token，安全设计）**
- 若实现联盟仓库，仅存储**联盟专属非交易性令牌**（如 联盟贡献点、联盟旗帜外观、赛季勋章），**不可兑换回三资源、不可被任何 Raid 掠夺**（不在 PVP §5.5 掠夺公式的 `StoredDef_r` 范围内）。
- 令牌有**独立上限**（与 SoftCap_r 解耦，见 §5.6），来源仅为联盟活动（集结参与、防守成功、情报贡献），**不进入三资源经济循环**，不构成通胀路径（R26 缓解）。
- 审计：任何令牌发放/消耗服务端留痕，可回溯，防脚本刷。

### 3.5 与 PVP / 经济 / 离线防御联动

**与 PVP 联动**
- Rally Raid 是 RaidCommand 的"多人合并"封装：分桶约束（PVP §5.1）、收益衰减（PVP §5.2）、护盾（PVP §5.3）、掠夺公式（PVP §5.5）、出击成本（PVP §5.5/经济 §5.3）全部逐字复用，不另起数值。
- 和平窗口/战时加成（PVP §3.2/§3.7）：Rally 发起/加入均须目标处和平窗口；误撞 PVE 给目标 +20% 防御 DPS。
- 友好 fire：同联盟禁止互攻（§3.1），RaidCommand 对同联盟目标服务端拒绝。

**与经济联动**
- 三资源不跨账号共享（经济 §3.2 红线）→ 本系统无转账通道（§3.4）。
- 战利品分摊：各成员份额受自身 SoftCap_r 封顶、溢出弃置（经济 §3.2/§3.4）；负值保护 `floor(max(0,...))`（经济 §6）。
- 出击成本：每位 Rally 参与者各自预缴 废料 50 + 生物质 20（经济 §5.3），构成双边消耗。
- 侦查成本 生物质 10 计入消耗闸门（R6）。

**与离线防御 AI 联动**
- **协防边界（关键）**：离线/断线者的堡垒由**自身账号**的 headless 模拟托管（离线 §3.2），盟友**不能直接操控他人堡垒或其单位**（违反账户隔离 + 服务器权威 R2 + 离线 headless 模型）。因此"协防"不实现为操控接管，而通过三层社会层实现：
  1. **情报预警**：联盟情报板/聊天推送"成员 X 正被 Y 集结进攻"，促其上线接管或激活护盾（离线 §4.4 上线战报同源）。
  2. **反击集结（Counter-Rally）**：盟友对进攻方发起 Rally Raid（进攻侧，引用 §3.2），以攻代守。
  3. **可选非掠夺增援令牌（Reinforce Token）**：盟友向离线成员捐赠消耗型增援令牌，该令牌**非三资源、不可掠夺**，仅在离线 headless 模拟中作为友方自动单位参战（引用离线 §3.2 模拟管线注入），消耗即消失、不入经济循环（R28 缓解）。其数量受 §5.6 上限约束。
- **离线 PVP 与 PVE 双线叠加**（离线 §6）：若离线成员同时被 Rally + PVE 波次，时间分桶+战时加成+串行结算+负值保护全部逐字复用，本系统不另起。

## 4. 玩家接口（三端统一抽象层 + SocialCommand / AllianceCommand）

### 4.1 抽象动词（P5 低门槛高深度）
统一为两类指令，各端仅做输入翻译，服务端为唯一真相源（引用 PVP §4.4）：
- **社交指令（Social）**：私聊 / 联盟聊天 / 侦查 / 举报 / 加好友 / 删好友。
- **联盟指令（Alliance）**：申请/邀请/踢出/退出/解散 / 发起集结/加入集结/取消集结 / 捐赠增援 / 设置自动增援。

### 4.2 各端适配
| 端 | 输入方式 | 关键适配 |
|---|---|---|
| PC | 社交面板（好友/联盟/聊天分页）+ 集结按钮 + 侦查图标 | 高信息密度，联盟情报板常驻侧栏；集结进度条 |
| 移动 | 底部「联盟」Tab + 大按钮（触摸 ≥48dp，美术 §7.4）+ 长按弹成员操作 | 聊天可折叠；集结确认二次弹窗防误触 |
| Web | 同 PC，限最大画布 | 禁用右键菜单冲突；键位与 PC 一致 |

### 4.3 统一指令结构（设计抽象，非实现代码）
```
SocialCommand {
  type: SendPrivateMsg | SendAllianceMsg | Scout | Report | AddFriend | RemoveFriend
  targetId: id                 // 目标玩家/联盟
  payload: string|scoutId      // 消息内容 / 侦查目标 ID
}
AllianceCommand {
  type: Apply | Invite | Kick | Leave | Disband | SetCoLeader
        | StartRally | JoinRally | CancelRally | DonateReinforce | SetAutoReinforce
  targetId: id                 // 目标成员/申请者
  rallyId: id                  // 集结会话（StartRally 后由服务端分配）
  unitIds: [id, ...]           // 集结/增援携带单位
}
```
> 客户端**仅发送上述动词指令**；关系状态、集结合并模拟、掠夺分摊、软上限判定、令牌发放全部以服务端为准（引用概念 R2）。SocialCommand / AllianceCommand 与 RaidCommand / DefendCommand / OfflineDefenseCommand 并列，构成三端统一指令抽象层（PVP §4.4）。

### 4.4 HUD 呈现（对齐美术 §7.3 三态 + §9 色盲）
- **联盟/社交入口**：运营态底部「联盟」Tab（冷蓝 `ENERGY_CYAN #48B6E8` 边框+旗帜图标，非纯色，美术 §7.3）；集结进度条用分段像素条 + 数字（数据双通道，美术 §7.1）。

- **战报推送**：自遭 Raid/Rally 结果、盟友战报（聚合）以护盾冷蓝/威胁暖橙区分敌我，配图标+文字；对比度 ≥ WCAG AA（美术 §9.2），色盲模拟开关可用（美术 §9.1/§9.3）。

### 5.3 收益分摊公式与示例（复用 PVP §5.5）
`Loot_total_r = StoredDef_r × R_loot(=0.5) × K_ratio_rally × K_online`
`K_ratio_rally = clamp((PS_def/PS_atk_combined)^0.5, 0.25, 1.0)`；`PS_atk_combined = Σ PS_atk_i`
分摊：`Loot_i_r = Loot_total_r × (PS_atk_i / PS_atk_combined)`，各自受 SoftCap_r 封顶、溢出弃置（经济 §3.2/§3.4）。

| 场景 | PS_atk 组合 | K_ratio_rally | Loot_total（占存量） | 人均（等分） | 对比单人 Raid |
|---|---|---|---|---|---|
| 3×T4 集结打 T4（在线 K_online=1.0） | 7000×3=21000 vs 7000 | 0.577 | 28.9% | ≈9.6% | 单人打同目标=50%（集结协同但人均更少，防farm） |
| 3×T4 集结打 T4（离线 K_online=0.10） | 21000 vs 7000 | 0.577 | 2.9% | ≈1.0% | 离线护盾外封顶逻辑一致 |
| 5×T4 集结打 T4（在线） | 35000 vs 7000 | 0.447（下限未触） | 22.4% | ≈4.5% | 人多→总掠夺更低（K_ratio 衰减） |
| 越级集结（5×T5 打 T3） | 50000 vs 2500 | 0.25（下限） | 12.5% | ≈2.5% | 越级收益触底，无 farm 价值（R1/R25） |

> 结论：集结总掠夺不超过"合并 PS 对应 K_ratio"上限且**目标仅结算一次**，杜绝多人各自全量掠夺；越级/多人均触发 K_ratio 衰减，与 PVP §5.2 收益衰减同源（R25）。

## 6. 边界与异常

| 场景 | 处理 |
|---|---|
| **成员退盟（在途 Rally）** | 退盟时若该成员 Rally 未结算：服务端撤销其单位与贡献占比，重新合并剩余 PS_atk 结算（目标仍仅结算一次）；其已缴**出击成本不退**（引用 PVP §5.5 预缴不退）。已结算入账的战利品不受影响。若退盟致剩余参与者 <2，Rally 自动转为剩余者单人 Raid（或取消，按剩余者选择） |
| **成员退盟（已结算）** | 其已入账份额保留（受软上限）；退盟后失去联盟情报/聊天权限，进行中新侦查/CD 失效 |
| **集结中目标激活护盾** | 护盾生效瞬间服务端取消该 Rally（目标不可选，PVP §3.3）；已缴出击成本不退；成员获通知 |
| **集结中目标入 PVE 波次** | 误撞给目标防御 DPS +20% 战时加成（PVP §3.7）；Rally 仍可发起但目标获加成；优先级保 PVE |
| **跨服（多服假设）** | 当前为单服架构；**联盟/好友/Rally/侦查均为服务器作用域**，不跨服互通（MMR/和平窗口/headless 均服务端权威，跨服状态不可达）。多服为远期，需独立网关，本 GDD 不覆盖 |
| **垃圾信息 / 举报** | 频率限制（§5.5）兜底；举报入审核队列；确认违规→禁言/移出联盟/上送账号处罚；恶意举报（超频）限权 |
| **Rally 成员断线** | 同 PVP §3.6：断线者单位按最后指令由服务端续算至结算；其贡献占比保留、份额按软上限入账；不奖励逃跑 |
| **友方互看布局后翻脸互攻** | 友好 fire 关闭仅限"同联盟期间"；退盟后恢复可攻，但布局仅在发起 RaidCommand 后由服务端只读下发（PVP §3.4），社交期看到的友方布局不缓存为攻击优势 |
| **增援令牌捐赠后受捐者离线被攻** | 令牌作为离线 headless 模拟友方单位参战（§3.5），消耗即消失；非三资源、不可被掠夺；捐赠者不退令牌 |
| **联盟满员申请** | 申请入队列或自动拒绝；盟主可踢人腾位 |
| **资源软上限溢出（分摊入账）** | 各成员份额超自身 SoftCap_r 部分弃置（经济 §3.2/§3.4），不进经济循环（R6） |
| **双线叠加（离线成员同时被 Rally + PVE）** | 逐字复用离线 §6：时间分桶+战时加成+串行结算+负值保护；护盾仅免 PVP 不免 PVE |

## 7. 依赖系统

| 依赖系统 | 对本系统的影响 |
|---|---|
| 实时 PVP 对战系统 | ① MMR 分桶（§5.1）约束 Rally 每位参与者；② 收益衰减 `K_ratio`（§5.2）逐字复用为 `K_ratio_rally`；③ 离线护盾（§5.3）触发 Rally 取消；④ 掠夺公式 `Loot_r`（§5.5）逐字复用，目标仅结算一次；⑤ RaidCommand/DefendCommand 抽象并列 SocialCommand/AllianceCommand；⑥ 和平窗口/战时加成（§3.2/§3.7）约束 Rally 发起 |
| 经济系统 | ① 三资源不跨账号共享红线（§3.2）→ 本系统无转账通道（§3.4）；② 软上限 `SoftCap_r`（§3.2）封顶各成员战利品份额、溢出弃置；③ 负值保护 `floor(max(0,...))`（§6）；④ 出击成本 废料50+生物质20（§5.3）每位 Rally 参与者预缴；⑤ 侦查成本 生物质10 计消耗闸门（R6） |
| 离线防御 AI | ① headless 模拟（§3.2）为 Rally 离线目标提供单次合并模拟内核；② 协防边界：盟友不直接操控他人堡垒（§3.5），经情报预警/反击集结/非掠夺增援实现；③ 双线叠加（§6）逐字复用；④ 上线战报（§4.4）与联盟战报推送同源 |
| 建造系统 | ① 布局锁定（§6）保证 Rally 模拟期目标布局稳定；② 网格坐标 `(col,row)∈[0,17]×[0,17]` 为侦查/互访只读镜像基础；③ 房间尺寸不影响社交层，仅影响 Rally 模拟（经 PVP 间接） |
| 美术圣经 | ① 聊天/情报/战报 UI 色盲友好 WCAG AA（§9）；② 威胁暖橙 `DANGER_ORANGE #E8762E`、护盾/系统冷蓝 `ENERGY_CYAN #48B6E8`、资源色（§2.7）；③ 三态 HUD 防御态视觉（§7.3）；④ tile 32×32 / 640×360 决定社交面板布局（§3）；⑤ 非色彩通道（图标+形状+文字，§9.1/§9.3） |

## 8. 设计风险与缓解

| # | 风险（引用概念 §12 / 关联 GDD） | 严重度 | 具体缓解策略 |
|---|---|---|---|
| R25 | **集结变成"多人 farm 同一弱目标"致不平衡/通胀**：若 Rally 允许多人各自模拟各自全量掠夺，5 人各掠 50% = 250% 漏洞；或弱目标被多桶越级围猎 | 高 | ① **目标仅结算一次**（合并 roster 单次模拟，§3.2）；② 每位参与者须满足 PVP §5.1 分桶约束（同桶/±1），越级不可加入（AC3）；③ 合并 PS_atk → `K_ratio_rally` 下限 0.25（PVP §5.2 逐字），人多/越级总掠夺反而更低（§5.3 示例）；④ 每人各自预缴出击成本（经济 §5.3），farm 无利 |
| R26 | **联盟仓库成为资源转移通道致 R6 通胀**：若联盟仓库存三资源，绕过单账号软上限并成掠夺/转账通道 | 高 | ① 服务端强制禁止三资源跨账号转账/援助（§3.4，违反经济 §3.2 红线即否决）；② 不提供可掠夺共享仓库；③ 若实现仓库仅存非交易性联盟令牌（不可兑三资源、不可被掠夺，§5.6）；④ 令牌独立上限、不进经济循环、审计留痕 |
| R27 | **情报共享泄露完整布局破坏 PVP 信息不对等**：敌方侦查若返回房间坐标/能源网/精确资源，则"先窥布局再决策"破坏实时对抗快感（P4）与公平 | 中 | ① 敌方侦查仅外部摘要（banded 资源、无布局/房间/精确值，§5.4 右列）；② 完整布局仅在该玩家实际发起 RaidCommand 后由服务端只读下发（PVP §3.4）；③ 友方摘要可见因友好 fire 关闭不构成 PVP 泄露（§3.1/§3.3）；④ 侦查有成本 生物质10 + CD 1h 防 spam |
| R28 | **协防/增援破坏离线 headless 模型或账户隔离（R2）**：盟友直接操控他人堡垒/单位违反服务器权威与账户隔离 | 中 | ① 盟友不直接操控他人堡垒/单位（§3.5，账户隔离 + 离线 headless 模型）；② 协防经情报预警/反击集结/可选非掠夺增援令牌三层实现；③ 增援令牌为消耗型、非三资源、不可掠夺、仅作 headless 友方单位、上限 ≤5（§5.6）；④ 跨服不互通（§6） |
| R29 | **退盟在途进攻致结算混乱/私吞战利品**：成员在 Rally 结算前退盟，若处理不当会重复结算或吞没他人份额 | 中 | ① Rally 发起即锁定成员贡献快照；② 退盟者未结算贡献撤销、重新合并剩余 PS 结算（目标仍一次，§6）；③ 已缴出击成本不退（PVP §5.5 一致）；④ 已结算份额按各自软上限正常入账不受退盟影响；⑤ 退盟致 <2 人转单人 Raid 或取消（§6） |

> 红线追踪：本系统以「R25 目标仅结算一次 + 分桶约束 + K_ratio 衰减」对冲**集结通胀/不平衡**；以「R26 禁转账 + 非交易性令牌」死守经济 **R6 资源不跨账号共享**红线；以「R27 外部摘要 + 布局仅 Raid 后下发」对齐 **PVP 信息不对等**；以「R28 账户隔离 + 非掠夺增援」守住 **R2 服务器权威**；以「R29 锁定快照 + 一次结算」处理退盟异常。四大设计红线（主导策略/经济失衡/认知过载/支柱漂移）中本系统主承载 **R6 经济失衡（联盟通道）** 与 **R2 账户隔离**，并以具体数值兜底，无设计红线遗漏。
