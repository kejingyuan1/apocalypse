## 1. 系统概述

能源网络系统是末日堡垒的 **供电底座（Power Backbone）**：能源房间（2×2）实时产生电力，各功能房间实时消耗电力，系统在每个结算 tick 做供需平衡；当供给不足（赤字）时按优先级降载（load shed），未获电房间进入「断能降级」状态，对应功能削弱甚至停摆。

一句话定义：**能源网络系统 = 把"供能(Energize)"从装饰性背景变成实时供需流——电力是瞬时流（production vs consumption），不是可囤积的库存资源；断电=防御沉默、生产停滞、破墙风险骤增。**

> **电力 vs 库存资源的本质区别（核心澄清）**：废料/晶体/生物质是**可累积的库存资源**（写入存量、受软上限约束、可被掠夺）；电力（Power Unit，PU）是**瞬时流**——每 tick 只计算 `Supply = Σ产能` 与 `Demand = Σ功耗` 的瞬时差，余额不入库、不囤积、不进经济循环、不可被掠夺。盈余（Supply > Demand）类比「软上限弃置」直接弃置（仅作为冗余缓冲降低断电概率）；赤字（Demand > Supply）触发降载，而非「欠费累计」。这一定性使电力永远不会成为第二条可通胀货币，从源头规避经济失衡（R6）。

## 2. 设计目标与验收标准

### 2.1 设计目标
- G1 电力即流：供需实时平衡，非库存；盈余弃置、赤字降载，从模型层杜绝电力通胀（R6 对冲）
- G2 供电制造布局决策：能源房小（2×2）需贴近多房间布网，强化「空间即策略」（P1）
- G3 断电有代价：防御/武器断能→开火降级、破墙风险骤增，使"电力冗余"成为真实战略项（P2）
- G4 晶体作高效燃料：复用经济系统晶体萃取速率，不另设晶体产出数值（R14 兜底）
- G5 双威胁同约束：波次与被 PVP 进攻时本方供电均受此系统约束（离线护盾除外），形成中枢一致性
- G6 三端一致：PC / 移动 / Web 共用同一套 PowerCommand 抽象（P5 低门槛高深度）

### 2.2 验收标准（MVP 门控）
| 编号 | 验收项 | 通过条件 |
|---|---|---|
| AC1 | 实时供需 | 每 tick 计算 Supply/Demand，HUD 供需条实时反映；盈余不入库、赤字触发降载 |
| AC2 | 断电惩罚生效 | 能源房断电→武器/防御 DPS 降至 30%；生产产出降至 30%（与经济 §6 逐字一致） |
| AC3 | 降载优先级 | 赤字时按「指挥 > 核心防御 > 生产 > 居住 > 装饰」顺序降载，Tier0 指挥永不降载 |
| AC4 | 波次联动 | 波次期间防御/武器断能→开火降级，攻防等式可被打破、破墙风险显式上升 |
| AC5 | PVP 联动 | 被进攻时本方能源房被毁→供给下降→级联断电，与离线护盾外逻辑一致 |
| AC6 | 晶体燃料对齐 | 晶体催化燃烧速率由经济系统 1.5/min 萃取速率覆盖，不另起晶体产出数值 |
| AC7 | 三端一致 | PC / 移动 / Web 同一 PowerCommand 在服务端结算结果完全一致 |

## 3. 核心机制

### 3.1 电力流模型（瞬时供需，非库存）
- **结算粒度**：与经济系统同频，1 tick = 1s；每 tick 服务端重算全网格供需（引用概念 R2 防作弊，客户端仅发 PowerCommand，状态以服务端为准）。
- **供给 `Supply`**：`Supply = Σᵢ Output(EnergyRoomᵢ)`，`Output` 来自 §5.1 产能表。
- **需求 `Demand`**：`Demand = Σⱼ Consumption(Roomⱼ)`，仅统计需电房间；城墙（0 PU）不计入。
- **平衡判定**：
  - `Supply ≥ Demand` → **供电充足**：所有需电房间全额运行；
  - `Supply < Demand` → **赤字（Deficit）**：进入降载流程（§3.3），按优先级切断最低 Tier 房间供电直至 `Demand_shed ≤ Supply`。
- **盈余处理**：`Supply − Demand` 的盈余**直接弃置**（不入库、不转晶体、不进经济循环），仅作为「断电缓冲裕度」显示于 HUD；其意义是吸收单房被毁造成的瞬时缺口，而非储存。
- **为何不引入「储能介质」**：概念既定晶体可作「储能介质」，但本系统**明确取「高效燃料」路线**——晶体燃烧提升单房产能，而非把电力存入晶体。理由：一旦电力可经晶体回填储存，就绕回「第二库存」，破坏 §1 的瞬时流模型并制造双源漂移（R14）。晶体始终只作燃料消耗侧，产出侧严格复用经济系统既有数值。

### 3.2 产能与功耗（引用建造 §5.1 面积矩阵）
- **能源房间（2×2，4 格）**：基础产能 `10 PU/间`（lv1）；可升级（不占新格，对冲建造 R5），升级缩放 `×(1 + 0.25×(lv−1))`，与经济系统生产房缩放因子一致（经济 §5.1）。
  - **晶体催化模式（Crystal Fuel）**：切换后产能 `14 PU/间`（lv1），燃烧晶体 `0.5/min/间`；`3 间催化共耗 1.5/min = 经济系统单座生产房晶体萃取速率（§5.1）`，证明催化燃料流完全由现有萃取/转化供给覆盖，**不另设晶体来源数值**。晶体存量受经济系统软上限约束（晶体 Base 200，+150/仓储，经济 §5.2）；不足时自动回落普通模式（不借贷、不扣负）。
- **功耗表（PU/间，lv1 基准）**：见 §5.2；升级轻微增耗 `×(1 + 0.10×(lv−1))`，维持「升级也吃电」的取舍。
- **邻接加成（引用建造 §3.5）**：能源⊕武器 射速 +15%（半径内）、能源⊕生产 产出 +10%——本系统提供「半径内供电」前提，二者叠加生效；断能则加成即时失效。

### 3.3 供需失衡与降载规则
- **触发**：任一 tick `Demand > Supply` 即进入赤字态。
- **降载优先级（Ladder，从低到高 shedding；高优先级最后断）**：

  | Tier | 房间 | 战略理由 |
  |---|---|---|
  | T4（最先断） | 实验 Lab / 仓储 Storage | 装饰/次级，断电影响最小 |
  | T3 | 居住 Housing / 医疗 Medical | 维持类，可短暂降级 |
  | T2 | 生产 Production | 经济产出，次于防御 |
  | T1 | 防御 Defense / 武器 Turret | 核心防御，尽量保 |
  | T0（永不降载） | 指挥 Command | 堡垒核心，断电=崩盘，强制满供 |

- **执行**：从 T4 起整间切断，按房间 id 确定性顺序（避免抖动）；若 T4 全断仍赤字，向上至 T3……直到 `Demand_shed ≤ Supply`；T0 指挥无论赤字多大均满供。
- **恢复**：能源房修复/升级/新供能恢复使 `Supply ≥ Demand` 时，被 shed 房间即时回到满供（含邻接加成），无冷却惩罚（与 "恢复供电即时回到 100%" 经济 §6 精神一致）。
- **确定性防抖**：同 Tier 多房间时按 `room_id` 升序 shed，保证断电名单稳定、HUD 不闪烁。

### 3.4 与建造系统联动（供电半径 / 战斗锁定）
- **供电半径**：能源房以自身为中心施加供电半径（半径 R 内房间视为「在网」；半径外房间即使全局有盈余也不计其功耗，等同断能）。半径内供电视为全局供需的一部分；本系统默认「全网格单一母线」模型（所有能源房并入同一电网，任意房间只要全局 Supply≥Demand 即满供），半径仅用于视觉/邻接判定，不强制分区——降低认知过载（R3）。
- **战斗锁定**：波次/PVP 进行中本方布局锁定（建造 §6）；**期间无法新建/移动能源房应急补能**——因此电网必须预先冗余设计，不能在断电时现场补救。这是本系统最关键的约束性联动（见 R12）。

### 3.5 与经济系统联动（晶体燃料 / 断能降级）
- **晶体燃料**：见 §3.2；晶体消耗计入经济系统晶体存量，速率由 1.5/min 萃取覆盖（§5.3），不另起数值。
- **断能降级（逐字对齐经济 §6）**：生产房脱离供电 → 产出降至在线基准 **30%**（brownout）；武器/防御断能 → DPS 降至 **30%**（与经济 §3.5「断能塔不耗弹药但 DPS 降级」一致）；恢复即时回到 100%（含邻接 +10%）。
- **波次消耗侧**：断能塔不耗弹药（废料）但 DPS 降级（经济 §3.5 / 波次 §3.5），本系统负责判定其「是否断能」。

### 3.6 与波次系统联动（承接战斗锁定 + 破墙）
- **断电对开火的直接影响**：波次进行中，若能源赤字导致防御/武器断能 → 其 DPS 降至 30%，直接拉低攻防等式 `堡垒总DPS × 波次时间窗口 ≥ TH_eff(w,Lv)` 左项（波次 §3.1）。等式失效 → 僵尸触及外墙、破墙（breach，波次 §3.4）→ 直冲内部房间/指挥核心 → 破防。
- **显式风险**：波次期防御断电 = 破墙风险骤增。HUD 在防御态以暖橙告警突出「断电防御房」数量（见 §4）。
- **战斗锁定的叠加**：因波次中不可改建（建造 §6），已发生的赤字无法靠加能源房缓解——玩家须在和平窗口预先布足冗余供电（R12）。
- **战时加成兼容**：若 PVP 误撞致目标获防御 DPS +20%（PVP §3.7），该加成在「满供」基准上叠加；断能房仍为 30% 基准，不享受全额加成。

### 3.7 与实时 PVP 对战系统联动（被攻同约束）
- **被进攻时供电同约束**：防守方（在线/离线托管）本方房间供电完全受本系统规则约束；进攻方可「瘫痪能源或防御房间以削弱」（PVP §3.4）——摧毁能源房 → `Supply` 下降 → 级联断电 → 防御/武器沉默，是进攻方核心破防路径。
- **离线护盾不豁免电力**：离线护盾（每日 1 次 8h、护盾外损失 ≤5%，PVP §5.3）仅约束 PVP 资源掠夺，**不豁免电网逻辑**；离线托管 AI 战斗时能源房仍在网则正常供电，能源房被毁同样级联断电（与波次 §6 离线处理一致）。
- **断线结算**：任一方断线，服务器按冻结电网配置继续模拟至结算（PVP §3.6）；重连不奖励断电逃避。

## 4. 玩家接口（三端统一抽象层 + 电网可视化）

### 4.1 抽象动词（P5 低门槛高深度）
统一为 4 类 Power 指令，各端仅做输入翻译，服务端为唯一真相源：
- **切换供能模式（SetEnergyMode）**：把能源房在「普通内燃 / 晶体催化」间切换（决定产能与晶体消耗）。
- **设降载策略（SetShedPolicy）**：AutoPriority（默认，按 §3.3 优先级）/ Balanced（均摊降载）/ Manual（手动指定优先断电房）。
- **手动降载（ManualShed）**：手动指定某房间优先断电（Manual 策略下）。
- **查询电网（QueryGrid）**：拉取当前供需快照（HUD 用，可选）。

### 4.2 各端适配
| 端 | 输入方式 | 关键适配 |
|---|---|---|
| PC | 点选能源房弹「供能模式」浮层 + 快捷键（E 切换 / P 降载策略） | 悬停显示该房产能、晶体燃烧率、全网供需条 |
| 移动 | 点选能源房 → 底部模式切换条 + 长按弹参数 | 触摸目标 ≥48dp；切换条大按钮防误触 |
| Web | 同 PC，限最大画布 | 禁用右键菜单冲突；键位与 PC 一致 |

### 4.3 统一指令结构（设计抽象，非实现代码）
所有端输入归一为：
```
PowerCommand {
  type: SetEnergyMode | SetShedPolicy | ManualShed
  roomId: id                 // 目标能源房间（SetEnergyMode 用）
  mode: Normal | Crystal     // Normal=废料内燃 10PU；Crystal=晶体催化 14PU
  policy: AutoPriority | Balanced | Manual   // 降载策略
  manualShedTarget: roomId   // ManualShed 时指定优先断电房间
}
```
> 客户端**仅发送上述动词指令**；供需计算、降载排序、断电判定、晶体扣减全部以服务端为准（引用概念 R2）。

### 4.4 电网可视化（对齐美术圣经 §2.2 / §7）
- **供需条（Power HUD）**：顶部独立电力条，填充色 `ENERGY_CYAN #48B6E8`（冷蓝能源·美术 §2.2/§0）；实时显示 `Supply / Demand` 数字 + 条形（数据双通道，美术 §7.1）。盈余段以满蓝显示「冗余缓冲」；赤字段（Demand > Supply）整条转 `DANGER_ORANGE #E8762E` 并脉冲（单层暖橙威胁体系，美术 §2.3）。
- **断电告警**：断电房间叠加 `DANGER_ORANGE` 描边 + ⚠ 图标（**非色彩唯一通道**，美术 §9.1 色盲铁律）；HUD 顶部计数「断电房 N」。防御态下该告警并入暖橙 vignette（波次 §4.3 / 美术 §7.3）。
- **能源辉光**：能源房常亮脉动 `ENERGY_CYAN` 光源（2s 呼吸），同屏常亮 ≤2（美术 §4.2 光源预算）；断能房辉光熄灭、转橙。
- **可访问性**：电力状态必配 ⚡（供）/ ⚠（断）图标 + 文字标签；对比度 ≥ WCAG 2.1 AA（美术 §9.2）；色盲模拟开关（美术 §9.1）下仍靠形状/图标区分。
- **三态 HUD（引用 PVP §4.3）**：运营态常驻电力条；防御/反攻态保留但弱化，断电告警升级为全屏暖橙脉冲，避免认知过载（R3）。

## 5. 关键数值

### 5.1 产能表（能源房间 · lv1 基准，每间）
| 模式 | 产能 (PU/间) | 等级缩放 | 燃料消耗 |
|---|---|---|---|
| 普通内燃 Normal | 10 | ×(1+0.25×(lv−1))，lv≤5 | 无（废料内燃内含） |
| 晶体催化 Crystal | 14 | ×(1+0.25×(lv−1))，lv≤5 | 晶体 0.5/min/间 |

> 升级不占新格（建造 §3.3 对冲 R5）；晶体催化燃烧 `0.5/min/间`，**3 间共 1.5/min = 经济系统单座生产房晶体萃取速率（经济 §5.1）**，无新晶体产出数值。

### 5.2 功耗表（PU/间，lv1 基准，引用建造 §5.1 / 波次 §5.3 尺寸）
| 房间类型 | 尺寸 | 功耗 (PU) | Tier | 断电惩罚（降至满值 %） |
|---|---|---|---|---|
| 城墙 Wall | 1×1 | 0 | — | 不受影响（纯承伤） |
| 居住 Housing | 2×2 | 1 | T3 | 人口上限临时失效、回复暂停 |
| 生产 Production | 3×2 | 2 | T2 | 产出 **30%**（经济 §6 逐字） |
| 医疗 Medical | 2×3 | 1.5 | T3 | 修复/治疗失效 |
| 仓储 Storage | 3×2 | 0.5 | T4 | 软上限缓冲失效（仍存库存） |
| 指挥 Command | 4×4 | 2 | T0 | **永不降载**（核心） |
| 实验 Lab | 3×3 | 3 | T4 | 科技/转化暂停 |
| 防御 Defense | 3×3 | 4 | T1 | 自动攻击 **DPS 30%**（波次 §3.4） |
| 武器 Turret | 2×2 | 3 | T1 | 开火 **DPS 30%**（波次 §3.4/经济 §3.5） |
| 能源 Energy | 2×2 | 0（净产出） | — | 自身被毁才减 Supply |

> 功耗升级轻微增耗 ×(1+0.10×(lv−1))；断电惩罚 DPS/产出 30% 软底**逐字对齐经济 §6 断能降级至 30%**。

### 5.3 晶体转化率（严格复用经济系统，不另设产出）
| 项 | 数值 | 来源 |
|---|---|---|
| 晶体萃取（生产房·晶体萃取模式） | 1.5/min/间 | 经济 §5.1（**权威产出数值，本系统不重定义**） |
| 实验转化（废料→晶体） | 8 废料 → 1 晶体（0.125） | 经济 §5.4 |
| 晶体催化燃烧（能源房） | 0.5/min/间 | **本系统新增消费参数**；3 间=1.5/min 恰由 1 座萃取房供给覆盖 |
| 晶体软上限 | Base 200，+150/仓储 | 经济 §5.2（催化耗尽受此约束） |

### 5.4 降载优先级表（赤字 shedding 顺序）
| 顺序 | Tier | 房间 | 断电后果 |
|---|---|---|---|
| 1（最先） | T4 | 实验 / 仓储 | 科技暂停 / 软上限缓冲失效 |
| 2 | T3 | 居住 / 医疗 | 人口上限失效 / 修复失效 |
| 3 | T2 | 生产 | 产出 30% |
| 4 | T1 | 防御 / 武器 | DPS 30% |
| 5（最后） | T0 | 指挥 | 永不降载 |

### 5.5 断电惩罚汇总（引用经济 §6 / 波次 §3.4）
| 受断电房间 | 惩罚 | 对齐来源 |
|---|---|---|
| 武器 / 防御 | DPS 降至 30% | 波次 §3.4 / 经济 §3.5 |
| 生产 | 产出降至 30% | 经济 §6 |
| 居住 | 人口上限临时失效 | 波次 §5.3（被毁后果类比） |
| 医疗 | 修复/治疗失效 | — |
| 指挥 | 永不降载 | 本系统 §3.3 |

### 5.6 稳态示例（供平衡 pass 校验）
- **Lv2（8×8，房间上限 7）**：1 能源(10) + 1 防御(4) + 1 武器(3) + 2 居住(2) + 1 生产(2) + 1 城墙(0) → Supply 10 / Demand 11 → 赤字 1，shed 1 居住（T3）→ 该居住断电。提示：Lv2 起步建议 2 能源房冗余。
- **Lv4（13×13，房间上限 16）**：3 能源(30) + 2 防御(8) + 2 武器(6) + 3 居住(3) + 2 生产(4) + 1 实验(3) + 1 医疗(1.5) + 1 仓储(0.5) + 1 指挥(2) → Supply 30 / Demand 28 → **充足，冗余 2 PU**。若仅 2 能源(20) → 赤字 8，需 shed T4+T3 部分 → 实验/居住断电。结论：每 ~4–5 间功能房配 1 能源房，+1 冗余为安全线。

## 6. 边界与异常

| 场景 | 处理 |
|---|---|
| 波次中断电 | 防御/武器 DPS 降至 30%，攻防等式左项下降；破墙风险骤增；因战斗锁定无法现场加能源房，须预冗余（§3.4/§3.6） |
| 能源房间被毁 | `Supply` 即时下降，重算供需；若转赤字→级联降载（§3.3）；修复后即时恢复（§3.3） |
| 断线重连 | 电网以服务端冻结配置为准，客户端仅渲染快照；重连不奖励断电逃避（PVP §3.6） |
| 离线结算 | 电网按最后在线配置稳态运行（供需恒定，无电力库存增益）；离线护盾不豁免电力逻辑（PVP §5.3 / 波次 §6）；托管失败核心被毁→重置 Lv2（软惩罚） |
| 晶体耗尽（催化模式） | 晶体 < 燃烧阈值时能源房自动回落普通模式（10 PU），不借贷、不扣负（经济 §6 转化房不足暂停精神一致） |
| 双倍消耗冲突 | 同一 tick 波次与 PVP 同时消耗，按服务端顺序串行，断电判定后统一结算（经济 §6 双倍冲突处理一致） |
| 战斗锁定中想补能 | 拒绝新建/移动能源房，HUD「战斗中不可改建」（建造 §6）；指令排队至战斗结束 |
| 全网格封锁（Supply=0） | 所有 T1–T4 断电，仅 T0 指挥满供；防御全沉默→几乎必破防，迫使玩家保障能源房存活（R11） |
| 盈余抖动 | 盈余弃置不入库；供需条平滑显示缓冲裕度，避免数字跳动造成误读 |

## 7. 依赖系统

| 依赖系统 | 对本系统的影响 |
|---|---|
| 建造系统 | ① 能源/功能房占地与数量决定 Supply/Demand 基线（§3.2，引用建造 §5.1 面积矩阵）；② 能源⊕武器+15%/能源⊕生产+10% 邻接加成前提由本系统「在网」提供（建造 §3.5）；③ 波次/PVP 战斗锁定禁止现场补能（建造 §6） |
| 经济系统 | ① 晶体催化燃烧消耗晶体存量，速率由 1.5/min 萃取覆盖（§5.3，引用经济 §5.1）；② 断能降级 30% 软底逐字对齐经济 §6；③ 晶体软上限约束催化上限（经济 §5.2）；④ 波次消耗侧弹药(废料)/应急(生物质)与断能判定联动（经济 §3.5） |
| 波次系统 | ① 防御(3×3)/武器(2×2) 需电才全额 DPS，断能→30% 直接削弱开火、抬升破墙风险（§3.6，引用波次 §3.4/§5.3）；② 战斗锁定使波次中断电不可现场修复（波次 §6） |
| 实时 PVP 对战系统 | ① 被攻时本方供电同约束，能源房被毁→级联断电（§3.7，引用 PVP §3.4）；② 离线护盾仅约束掠夺、不豁免电网（PVP §5.3）；③ 断线服务器续算冻结电网（PVP §3.6） |
| 美术圣经 | ① 能源色 `ENERGY_CYAN #48B6E8` 供供需条/辉光、`DANGER_ORANGE #E8762E` 断电告警（§4.4，引用美术 §2.2/§2.3）；② tile 32×32/640×360 决定 HUD 布局与光源预算（美术 §3/§4.2）；③ 非色彩通道 + WCAG AA 色盲友好（美术 §9） |

## 8. 设计风险与缓解

| # | 风险 | 严重度 | 具体缓解策略 |
|---|---|---|---|
| R11 | **电网级联崩溃**：能源房被毁（波次破墙/PVP 瘫痪）→ Supply 骤降→级联断电→防御全沉默→雪崩破防 | 高 | ① T0 指挥永不降载，保留最后指挥能力；② 断电 DPS 仍有 30% 保底（非全停），争取翻盘窗口；③ 降载确定性顺序防抖动；④ HUD 断电告警提前量 + 和平窗口预冗余建议（§5.6）；⑤ 能源房建议内嵌/贴核心布防降低被毁率 |
| R12 | **布局锁定致波次中断电无法应急补能**：战斗锁定（建造 §6）禁止现场加能源房，赤字一旦发生只能硬扛 | 高 | ① 强调「预规划冗余」：每 4–5 功能房配 1 能源房 +1 冗余（§5.6）；② HUD 在和平窗口即预警「下波潜在赤字」；③ 离线托管按冻结配置稳态运行，无隐患；④ 战斗锁定本身防作弊（R2），不可为补能放开 |
| R13 | **多系统叠加认知过载**：电网+波次+PVP 同时暴露，玩家 overwhelmed（R3） | 中 | ① HUD 三态互斥（PVP §4.3），电力条仅在运营态常驻、防御/反攻态弱化；② 供需条精简为单条 + 数字，断电用 ⚠ 图标非纯色（美术 §9）；③ 降载默认 AutoPriority 免手动决策；④ 冗余缓冲概念用「满蓝=安全」直觉表达 |
| R14 | **晶体燃料致经济漂移**：能源大量燃烧晶体改变晶体供需，或引入第二晶体来源 | 中 | ① 晶体**仅作燃料消耗侧**，不回填储存电力（§3.1 明确取「高效燃料」弃「储能介质」）；② 燃烧速率 0.5/min/间 由现有 1.5/min 萃取覆盖，不另设晶体产出（§5.3）；③ 晶体软上限约束催化上限（经济 §5.2）；④ 监控钩子：若晶体长期贴近软上限且利用率<20%，下调催化增益或上调萃取比 |
| R15 | **离线电力结算歧义（凭空增益）**：离线时电网被误算为产出/囤积电力，违背「非库存」模型 | 中 | ① 离线电网按最后在线配置**稳态运行**，供需恒定、无电力库存增益（§6）；② 离线护盾不影响电力（仅 PVP 资源，PVP §5.3）；③ 晶体催化离线按同速率燃烧但受离线衰减精神约束（不增存量）；④ 与经济离线衰减 §3.3 一致：离线不产生额外资源/电力 |

> 红线追踪：本系统以「电力=瞬时流、盈余弃置、赤字降载」模型从源头规避 **R6 经济失衡**（无第二可通胀货币）；R11/R12 为能源系统自身高严重度风险（级联崩溃/锁定不可补能），R13/R14/R15 分别兜底 **R3 认知过载**、**晶体经济漂移**、**离线增益歧义**，无设计红线遗漏。
