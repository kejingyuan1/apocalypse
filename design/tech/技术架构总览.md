## 0. 架构总原则（贯穿全文的硬约束）

本架构必须同时满足 Phase 2 八份 GDD 的以下技术契约，任何偏离均视为缺陷：

1. **服务器权威（唯一真相源）**：客户端**仅发送动词指令**（GridCommand / HarvestCommand / WaveCommand / PowerCommand / ResearchCommand / RaidCommand / DefendCommand / OfflineDefenseCommand / SocialCommand / AllianceCommand）。所有校验、结算、伤害、资源变更以服务端为准（引用概念 §10.2 / R2）。
2. **固定 1s tick + 整数化中间量**：经济（§3.1）、能源（§3.1）、波次/离线 AI（§3.2）结算粒度统一为 `1 tick = 1s`；伤害/HP/资源用定点或定规四舍五入，禁止平台相关浮点不确定源（离线 AI §3.2 / R20）。
3. **确定性可重放**：所有随机性取自 `seed = hash(raidId, defenderId, startTick)` 驱动的 PRNG；同输入同输出，PC/移动/Web 服务端重放 bit 一致（离线 AI §3.2 / R20）。
4. **战斗内核同源**：在线防守、波次 PVE、离线 headless AI 复用同一份 A* + breach + 开火 + 电网 + 科技结算逻辑，无离线/在线专属战斗数值（离线 AI §1 / §3.3）。
5. **三端指令抽象一致**：各端仅做输入翻译，同一 `*Command` 在服务端结果完全一致（各 GDD AC5/AC7/AC8 验收项）。

## 1. 总体架构分层

系统分为三层，物理与逻辑边界清晰：

```
┌──────────────────────────────────────────────────────────────────┐
│  CLIENT（Godot 4 游戏端 · PC/Mobile/Web 导出）                      │
│  res://client/  res://platform/{pc,mobile,web}/                     │
│  · 输入翻译 → *Command（鼠标/触屏/键盘统一抽象）                     │
│  · 快照插值（Snapshot Interpolation）+ 本地预测（Prediction）        │
│  · 渲染：640×360 设计分辨率整数缩放、Nearest 过滤、HUD 三态          │
│  · 不持有权威状态，仅渲染服务端下发的只读镜像                         │
└───────────────────────────────┬──────────────────────────────────┘
                                 │  (上行) *Command 指令流
                                 │  (下行) Snapshot 状态快照 / 战报
                                 ▼
┌──────────────────────────────────────────────────────────────────┐
│  SHARED CORE（确定性模拟内核 · 无渲染依赖 · 纯逻辑）                  │
│  res://core/  res://systems/{building,economy,wave,power,tech,...}  │
│  · 平台无关 GDScript/C#；固定 1s tick；种子化 PRNG；整数化结算        │
│  · 同时被 SERVER（权威运行）与 CLIENT（本地预测）复用 → 同源防漂移    │
│  · 八系统 *Command handler + *System 结算逻辑                        │
└───────────────────────────────┬──────────────────────────────────┘
                                 │  (同构二进制 / 同套代码)
                                 ▼
┌──────────────────────────────────────────────────────────────────┐
│  SERVER（Godot Headless / 专用权威服务）                             │
│  · 权威 tick 循环：采集指令 → 确定性结算 → 广播快照                  │
│  · Matchmaking / Raid 服务（MMR 分桶、集结合并模拟）                  │
│  · Persistence（账号作用域存档、战报/回放日志）                       │
│  · 反作弊：心跳保活 + 战斗回放审计 + 异常回滚                        │
└──────────────────────────────────────────────────────────────────┘
```

**关键设计点**：`SHARED CORE` 是架构灵魂。它把八系统的**结算逻辑**与**渲染**彻底解耦——同一份 `core/` 代码被服务器 `headless` 运行（权威）与客户端运行（预测/回放），从根本上保证"离线 AI 与在线 PVE/PVP 战斗内核同源"（离线 AI §1 铁律），并让确定性回放可跨平台审计。

## 2. Godot 4 项目结构

### 2.1 目录结构（res://）

```
res://
├── core/                      # 确定性模拟内核（无 Godot 渲染依赖）

│   ├── tick/                  # FixedTickScheduler（固定 1s 步长循环）

├── systems/                   # 八系统结算逻辑（纯逻辑，挂载于 core）

│   ├── persistence/           # 存档序列化、DB 适配
│   └── anticheat/             # 心跳、回放审计、回滚
├── autoload/                  # 全局单例（见 §2.3）
├── assets/                    # 美术资产（遵循美术圣经 §3/§6 命名与预算）
```

### 2.3 Autoload 单例

| 单例 | 职责 | 说明 |
|---|---|---|
| `TuningDB` | 加载全部数值表（面积矩阵/软上限/BaseCV/僵尸属性/科技节点） | 八 GDD 数值集中存放，禁止硬编码散落 |
| `CommandRouter` | 客户端：把输入翻译为 `*Command` 并上行；服务端：分发到对应 System handler | 三端抽象统一层 |

| `SaveManager` | 客户端本地缓存（离线快照、设置） | 服务端快照权威，本地仅缓存 |
| `NetManager` | 平台传输适配（WebSocket / WebRTC / TCP） | 见 §5 平台差异隔离 |
| `EventBus` | 系统间解耦信号（资源变更/断电告警/HUD 三态切换） | 渲染与逻辑解耦 |

### 2.4 八 GDD 系统 → 模块映射表

|---|---|---|---|

| 离线防御 AI | `OfflineDefenseCommand{SetAutoPriority\|ActivateShield}` | `systems/offline_ai` | headless 复用波次内核；seed 驱动 PRNG；K_online=0.10 封顶 5% |
| 社交联盟 | `SocialCommand{...}` + `AllianceCommand{...}` | `systems/social` | 关系模型；Rally 合并单次模拟；目标仅结算一次；经济红线禁转账 |

## 3. 服务器权威网络架构

### 3.1 架构图

```
                    ┌──────────────────────────────────────────────┐
                    │            Authoritative Server              │
                    │  (Godot Headless · 多实例/分服)               │
                    │                                               │
   PC ──┐           │   ┌────────────────────────────────────┐    │
   Mobile├──cmd─────▶│──▶│  SimulationLoop (Fixed 1s Tick)      │    │
   Web ──┘           │   │  ┌────────────┐  ┌──────────────┐  │    │
                    │   │  │ CommandQueue│─▶│ Core Systems  │  │    │
                    │   │  └────────────┘  │ (8 *System)   │  │    │
   PC ──┐           │   │  ┌────────────┐  │ + OfflineAI   │  │    │
   Mobile├──◀snapshot│◀──│──│ SnapshotBus │◀─│ Engine(headless)│ │    │
   Web ──┘           │   │  └────────────┘  └──────┬───────┘  │    │
                    │   │                          │ snapshots  │    │
                    │   └──────────────────────────┼──────────┘    │
                    │             ┌────────────────┼───────────┐  │
                    │             ▼                ▼           ▼  │
                    │      Matchmaking/MMR   Persistence(DB)  Replay│
                    │      (Raid/Rally 会话)  (账号作用域存档) 审计 │
                    └──────────────────────────────────────────────┘

   指令流方向：Client → Server（仅动词）
   状态流方向：Server → Client（只读快照 + 战报）
   反作弊：心跳超时即判负；回放可重放审计；异常直接回滚（概念 R2）
```

### 3.2 Matchmaking / Raid 服务

- **MMR 分桶**（PVP §5.1）：`PS = Σ[BaseCV×(1+0.5×(lv-1))] + TechBonus + 0.1×BlockedCells`；仅同桶/±1 桶可匹配，跨 2 桶返回空列表。
- **Raid 会话生命周期**：发起校验（目标 ≥Lv4 / 非护盾 / 和平窗口）→ 进入"反攻态"→ 服务端以 `LayoutSnapshot`（只读镜像）注入 attackerRoster → 单次模拟结算。
- **Rally 集结**（社交 §3.2）：合并 roster → **目标仅结算一次** → 按 PS 贡献分摊（`Loot_i_r = Loot_total_r × PS_atk_i/PS_atk_combined`），各自软上限封顶；退盟/断线按快照重合并，出击成本不退。
- **离线托管**：防守方离线/断线 → `OfflineDefenseEngine` 用 `LayoutSnapshot + seed` headless 模拟，`K_online=0.10` 封顶 5%。

### 3.3 状态同步（Snapshot Sync）

- **上行**：客户端仅发 `*Command`；本地做预测（单位移动插值、建造预览），但落盘/结算以服务端为准。
- **下行**：服务端每 1s tick 广播一次 `WorldSnapshot`（房间 HP / 单位位置 / 资源 / 电网状态 / 波次进度）。客户端在 60fps 渲染帧间对快照做**插值**（位置/血条），并在收到新快照时**校正**预测偏差（reconciliation）。
- **战斗锁定**：波次/PVP 进行中，`GridCommand` 的 Place/Upgrade/Demolish 被服务端拒绝（建造 §6），HUD 置灰。
- **断线续算**：任一方断线，服务端冻结最后有效指令 + 托管 AI 继续至结算（PVP §3.6）；重连可看回放。

### 3.4 Tick 循环（固定 1s）

```
loop (server authoritative):
  t = next_fixed_tick()               # 严格 1s 步长，不随帧率波动
  collect Commands from queue (sorted deterministically by id)
  for each System in fixed order:     # 固定结算顺序，杜绝抖动
    BuildingSystem.apply(GridCommand)
    EconomySystem.tick()              # 产出/软上限/离线衰减
    PowerSystem.solve()               # Supply/Demand + 降载
    TechSystem.tick()                 # 转化/研究推进
    WaveSystem.tick()                 # 调度/A*/breach/开火/消耗
    PvpSystem.tick()                  # Raid/Defend 结算
    OfflineAIEngine.tick()            # headless 托管战斗
  rng.advance(seed)                   # 仅用于 tiebreak/暴击，种子驱动
  broadcast(WorldSnapshot(t))         # 下行快照
```

> 固定顺序 + 整数化中间量（`core/math/FixedPoint`）+ 种子化 PRNG，保证三端重放 bit 一致。

### 3.5 确定性回放（Deterministic Replay）

- **记录**：`(seed, [Command_i @ tick_i], startTick)` → 战报 `OfflineBattleReport` + 模拟日志持久化（概念 §10.2 远期层回放）。
- **重放**：用相同 `seed` + 相同指令流 + 相同 `core/` 代码，三次独立服务器重放结果 bit 一致（离线 AI AC3）。
- **审计**：反作弊直接比对重放结果 vs 上报结果，不一致即判违规回滚（R2）。

## 4. 多平台构建链

### 4.1 四端导出配置要点（export_presets.cfg）

| 平台 | 导出目标 | 关键配置 | 约束/注意 |
|---|---|---|---|
| **PC（Steam/itch.io）** | Windows/macOS/Linux 原生 | 键鼠热键、高信息密度 HUD、`stretch` 2x/3x | 无线程限制；可开 Bloom；可跑本地预测与轻量回放 |
| **Web** | HTML5 / WebAssembly | WebRTC 传输（WebSocket 兜底）、禁用右键菜单、限最大画布 | **单线程**：headless 模拟全在服务端，客户端仅渲染；禁用 Godot 多线程/线程相关特性；纹理压缩用 basis/兼容格式 |
| **iOS** | iOS 导出 | 触控 ≥48dp、Safe Area、App Store 合规 | 禁用动态代码；GDExtension 需对应架构 slice |
| **Android** | Android 导出 | 触控 ≥48dp、竖屏重排、移动 GPU 预算 | 权限最小化；后台断线触发托管 |

### 4.2 共享逻辑层与平台差异隔离

- **共享层（平台无关）**：`core/` + `systems/` + `server/` 全部为纯逻辑，不引用任何平台 API；GDScript（或 C#）编写，跨四端同构运行。
- **平台适配层（隔离差异）**：
  - **输入**：`client/input/` 把 PC 鼠标/键盘、移动触屏、Web 键鼠分别翻译为同一 `*Command` 结构（各 GDD §4.2 适配表）；触摸目标 ≥48dp（美术 §7.4）。
  - **网络传输**：`NetManager` 抽象；PC/iOS/Android 用 TCP/WebSocket，Web 用 WebRTC（`platform/web/` 特化），`CommandRouter` 不感知底层。
  - **渲染预算**：`platform/*/render_config.cfg` 调同屏精灵上限（PC 600 / 移动 300 / Web 400）、动态光源（PC 6 / 移动·Web 4）、单图集尺寸（512/1024）、Bloom 开关（美术附录 A.2）。
  - **整数缩放**：全局 `stretch_mode=viewport`、`stretch_aspect=expand`、`texture_filter=Nearest`；设计分辨率 640×360，缩放档 2x/3x（美术 §3.2）。

> **原则**：任何"平台 if 分支"只允许出现在 `platform/` 与 `client/input/`/`NetManager`；`core/` 与 `systems/` 必须零平台分支，确保确定性内核四端一致。

## 5. 数据模型与持久化

### 5.1 核心数据模型

| 实体 | 字段（要点） | 来源 |
|---|---|---|
| **Grid** | `18×18` cell → `{room_id | empty}`；坐标 `(col,row)∈[0,17]×[0,17]` | 建造 §3.1 |
| **Room** | `id, type, level(1–5), (c0,r0,w,h), rotation, hp`；指挥 Command 唯一 4×4 不可拆 | 建造 §5.1 / 波次 §5.3 |
| **Resource** | `scrap/crystal/biomass` + `population`；`SoftCap_r = Base_r + BonusPerStorage_r×N_storage` | 经济 §3.2/§5.2 |
| **Wave** | `waveNo, interval(T(Lv)), FortMul(Lv), N_eff, breach[]` | 波次 §3.1/§3.3 |
| **Power** | `Supply, Demand, shedLadder(T4→T0), energyConfig{mode}` | 能源 §3.1/§3.3 |
| **Tech** | `T1-A..T4-B` 各节点 `level`；绑定玩家档案（永久） | 科技 §5.2 |
| **PVP** | `raidId, attackerRoster, PS_atk/def, K_ratio, K_online, shieldState` | PVP §5 / 离线 AI §3.2 |
| **Social** | `friends[], alliance{role}, rally{rallyId, members[]}, intel[]` | 社交 §3 |

### 5.2 序列化与存储

- **存档（账号作用域）**：服务端 DB 持久化 `GridSnapshot + Resource + Tech + Social + ShieldCD`；格式建议 MessagePack/二进制（紧凑、可版本化）。客户端 `SaveManager` 仅缓存最新快照用于断线重建（非权威）。
- **离线快照（OfflineDefenseEngine 输入）**：

  ```
  LayoutSnapshot { grid, energyConfig, techBonuses{T1-A..T3-B}, autoPriority{roomId→H/N/L} }
  ```
  纯服务端权威生成，客户端提交的离线快照若与 server 不符直接拒绝（离线 AI AC7 / R22）。
- **回放日志**：`(seed, [Command @ tick], startTick)` + `OfflineBattleReport`；用于反作弊审计与"战斗回放"（概念 §10.2）。
- **版本兼容**：所有序列化带 `schema_version`；升级时做迁移，不破坏旧档。

## 6. 关键技术风险与缓解

| # | 风险 | 严重度 | 架构层缓解 |
|---|---|---|---|
| R-A | **确定性跨端漂移**（浮点/时钟/线程） | 高 | 固定 1s tick + `core/math/FixedPoint` 整数化 + 种子化 PRNG（禁 System.Random/时钟）；`core/` 零平台分支；三端同构二进制 |
| R-B | **作弊（客户端篡改布局/资源/穿墙）** | 高 | 服务器权威：客户端仅发 `*Command`；路径/伤害/资源服务端重算；心跳超时判负；回放审计 + 异常回滚（R2） |
| R-C | **Web 单线程/传输约束** | 中 | headless 模拟全在服务端，Web 客户端仅渲染+插值；`NetManager` 用 WebRTC；禁用 Godot 线程特性 |
| R-D | **多平台输入不一致** | 中 | `client/input/` 统一抽象层翻译为同一 `*Command`；触摸 ≥48dp；服务端为唯一真相（各 GDD AC5/AC8） |
| R-E | **战斗内核漂移（在线/离线/PVE 三套数值）** | 高 | `systems/wave` 的 A*+breach+开火内核被 `offline_ai`/`pvp` 复用；离线 AI 无专属战斗数值（离线 AI §3.3 逐字对齐清单） |
| R-F | **经济通胀（R6）** | 高 | 软上限弃置 + 离线衰减 + 出击成本 + 波次消耗四闸门；电力为瞬时流不入库；社交层禁三资源跨账号转账（经济 §8.1 / 社交 §3.4） |
| R-G | **PVE/PVP 双线认知过载（R3）** | 中 | HUD 三态互斥；时间分桶（仅和平窗口可 PVP）；误撞给防御 DPS+20% 战时加成（PVP §3.7） |
| R-H | **断线接管竞态（R23）** | 中 | 控制权交接严格在 1s tick 边界；不重演已模拟 tick；保留已发生 HP/资源变更（离线 AI §6） |
| R-I | **网格/资源存档膨胀** | 低 | 二进制紧凑序列化 + `schema_version` 迁移；快照按账号分片存储 |
