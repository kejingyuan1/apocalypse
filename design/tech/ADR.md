## ADR-001 引擎选型：采用 Godot 4

- **状态**：Accepted
- **决策**：本作全平台（PC / 移动 / Web）统一采用 **Godot 4** 作为游戏引擎，否定 Unity 与自研引擎。
- **理由（含备选对比）**：
  - **备选 A — Unity**：Unity 的 WebGL 导出长期体积大、启动慢、线程模型与 Web 不一致，且自 2023 起收费/授权政策不确定，对独立团队构成商业风险；其 DOTS/ECS 虽强但学习曲线陡、与"确定性 1s tick + 整数化"的轻量需求不匹配（杀鸡用牛刀）。
  - **备选 B — 自研引擎**：可 100% 控制确定性内核，但需自造渲染/输入/资源/导出四端管线，工期与维护成本远超本项目规模，且美术圣经 §3/§4 已明确依赖 Godot 的 `Light2D` / `WorldEnvironment` / `Nearest` 过滤等现成能力。
  - **选定 Godot 4 的根据**：① 原生支持 PC/移动/Web 四端单代码库导出，与"多平台同步"硬约束契合；② `stretch_mode=viewport` + `Nearest` 过滤天然支撑 tile 32×32、设计分辨率 640×360 整数缩放（美术 §3.2）；③ GDScript/C# 纯逻辑层与渲染层易解耦，便于抽出"确定性核心"被服务端 headless 复用（架构 §1/§2）；④ 开源免费、无授权风险；⑤ 美术圣经 §0 已裁定引擎为 Godot 4，与概念/美术基线一致。
- **影响**：
  - 正：四端同构、导出成本低；确定性内核可 headless 复用；美术管线零摩擦。
  - 负/约束：Godot Web 导出为单线程（WebAssembly），故**权威模拟必须置于服务端**，客户端仅渲染（见 ADR-002/ADR-003）；GDExtension 需为每个移动架构单独编译切片；大型 3D/复杂着色器非其强项（本作 2.5D 像素无需）。
  - 待办：锁定 Godot 4.x 具体版本，固化 `export_presets.cfg`（架构 §4.1）。

## ADR-002 网络架构：服务器权威 + Headless 确定性模拟

- **状态**：Accepted
- **决策**：采用 **服务器权威（Server-Authoritative）** 架构；客户端**仅发送动词指令**（`*Command`），所有状态以服务端为准；离线/断线被攻时由服务端运行 **headless 确定性模拟**（复用波次战斗内核）托管。明确否定 P2P 与帧同步（Lockstep）。
- **理由（含备选对比）**：
  - **备选 A — P2P（对等网络）**：无中心服务器，玩家间直连。优点省服务器成本；缺点：任一端被入侵即可篡改本地状态（布局/资源/穿墙），与概念 R2「作弊」高严重度风险直接冲突；且离线玩家无法作为对等节点存在，离线防御无从托管。
  - **备选 B — 帧同步（Lockstep）**：所有客户端按相同输入帧推进、各自计算。优点带宽低；缺点：① 要求**所有端**浮点/指令完全一致，移动/Web/PC 跨平台浮点漂移极难保证（与离线 AI R20 直接冲突）；② 一卡全卡（一慢客户端拖垮全局）；③ 离线玩家无法"同步"；④ 反作弊仍需服务器校验，得不偿失。
  - **选定服务器权威 + headless 的根据**：① 概念 §10.2 / R2 明确要求"所有状态以服务端为准，客户端仅发输入"；② 八 GDD 全部 `*Command` 抽象即"仅动词"契约（建造 §4.3、经济 §4.3、波次 §4.4、能源 §4.3、科技 §4.3、PVP §4.4、离线 AI §4.3、社交 §4.3）；③ 离线 AI 要求"确定性 headless 模拟"复用波次内核（离线 AI §1/§3.2）；④ 服务器权威天然支持断线续算、回放审计、MMR 分桶（PVP §5.1）。
- **影响**：
  - 正：彻底封堵客户端篡改（R2）；离线防御与在线 PVP/波次共用战斗内核，无双重惩罚/豁免（离线 AI §1）；回放可审计。
  - 负/约束：需运维权威服务器（成本）；客户端需做**快照插值 + 本地预测 + 校正**（架构 §3.3）以掩盖延迟；战斗锁定期间布局不可改（建造 §6）。
  - 待办：实现 `server/simulation_loop` 固定 1s tick 主循环 + `SnapshotBuffer` 插值（架构 §2.3/§3.4）。

## ADR-003 多平台策略：共享核心逻辑层 + 平台适配层

- **状态**：Accepted
- **决策**：将游戏逻辑拆分为 **平台无关共享核心层**（`core/` + `systems/` + `server/`，纯逻辑、零平台分支）与 **平台适配层**（`platform/{pc,mobile,web}/` + `client/input/` + `NetManager`），隔离输入、网络传输、渲染预算与导出差异。
- **理由（含约束分析）**：
  - **Web 约束**：浏览器为单线程（WebAssembly），Godot Web 导出不可用多线程；因此**权威模拟必须全在服务端**，Web 客户端只渲染+插值；网络用 WebRTC（WebSocket 兜底），禁用右键菜单冲突（各 GDD §4.2）。
  - **移动约束**：小屏需触控目标 ≥48dp（美术 §7.4）、竖屏重排、GPU 预算收紧（同屏精灵 300、动态光源 4、单图集 512，美术附录 A.2）；后台易断线→触发托管。
  - **PC 约束**：高信息密度、键鼠热键、可开 Bloom、无线程限制。
  - **被否决方案 — 每端独立代码库**：会导致四套结算逻辑漂移，破坏"确定性内核同源"（离线 AI §1 铁律）与三端指令一致验收（各 GDD AC5/AC8），维护成本 ×4，否决。
  - **选定共享+适配的根据**：架构 §1/§4.2 明确"任何平台 if 分支只允许出现在 platform/ 与 client/input/"，`core/`、`systems/` 必须零平台分支 → 保证四端同构、确定性一致。
- **影响**：
  - 正：四端同构二进制，确定性审计可跨端；新增平台仅加适配层；三端指令一致验收可控。
  - 负/约束：适配层需为 Web 特化 `NetManager`（WebRTC）、为移动特化 `render_config`（预算）；GDExtension 移动切片需单独构建。
  - 待办：固化 `platform/*/render_config.cfg` 与四端 `export_presets.cfg`（架构 §4.1/§4.2）。

## ADR-004 确定性回放：固定 1s tick + 整数化 + 种子化 PRNG

- **状态**：Accepted
- **决策**：全局采用 **固定 1s tick** 步长循环；所有伤害/HP/资源结算使用**整数化或定规四舍五入中间量**；所有随机性（目标 tiebreak、破墙锁定、spawn 顺序、暴击）取自 **种子化 PRNG**（`seed = hash(raidId, defenderId, startTick)`），禁用时钟/手表/平台相关浮点不确定源。直接承接离线防御 AI R20。
- **理由（含备选对比）**：
  - **备选 A — 可变步长 + 浮点**：实现简单，但跨平台（PC float / 移动 / Web wasm）浮点运算顺序与精度差异会导致重放漂移，使"战斗回放审计"失效，R2 作弊兜底崩塌（离线 AI R20 高严重度）。否决。
  - **备选 B — 仅服务端记录结果不重放**：节省存储，但失去"可审计可重放"的反作弊能力，且离线 AI 要求"同输入三次重放 bit 一致"（离线 AI AC3）。否决。
  - **选定固定 tick + 整数化 + 种子 PRNG 的根据**：① 经济 §3.1 / 能源 §3.1 / 波次 §3.4 / 离线 AI §3.2 四系统统一 `1 tick = 1s`，天然对齐；② 离线 AI R20 明确要求"固定 1s tick + 整数化中间量 + seed 驱动 PRNG"；③ 整数化（或定点 `FixedPoint`）消除浮点漂移，种子 PRNG 消除随机不确定性，二者合起来保证**三端重放 bit 一致**；④ 固定 tick 顺序（架构 §3.4）杜绝系统间结算抖动。
- **影响**：
  - 正：回放可审计（R2 兜底）、离线 AI 与在线战斗内核同源（离线 AI §1）、跨端一致性验收可证明。
  - 负/约束：整数化需在 `core/math/` 统一封装，禁止散落浮点比较；PRNG 必须自实现（不可用品台 `rand()`）；动画/手感用客户端独立插值，不进模拟内核。
  - 待办：落地 `core/rng/`（种子化 PRNG）、`core/math/`（FixedPoint + rounding）、`core/tick/`（FixedTickScheduler）（架构 §2.1/§3.4/§3.5）。

## ADR-005 数据持久化与反作弊：账号作用域存档 + 回放审计 + 经济红线

- **状态**：Accepted
- **决策**：
  1. **持久化**：采用**账号作用域**服务端存档（GridSnapshot / Resource / Tech / Social / ShieldCD），二进制紧凑 + `schema_version` 迁移；客户端仅缓存权威快照用于断线重建。离线防御输入为服务端生成的 `LayoutSnapshot`（客户端伪造快照直接拒绝）。
  2. **反作弊**：心跳保活 + **战斗回放审计**（记录 `seed + [Command@tick]`，可重放比对）+ 异常回滚；断线超时即判负。
  3. **经济红线**：在服务端持久化与结算层死守"三资源（废料/晶体/生物质）不跨账号共享"（经济 §3.2 红线）；社交层禁直接转账/可掠夺共享仓库，联盟令牌非交易性、不可兑三资源、不可被掠夺（社交 §3.4）。
- **理由（含备选对比）**：
  - **备选 A — 客户端本地存档权威**：玩家可改本地文件刷资源/布局，与 R2 直接冲突；且多平台进度无法同步（概念 §6.3 跨平台云存档）。否决。
  - **备选 B — 允许联盟共享仓库存三资源**：看似便利，但绕过单账号软上限、成为掠夺/转移通道，直接触发 R6 经济失衡（社交 R26 高严重度）。否决。
  - **备选 C — 仅心跳无回放**：心跳可发现掉线，但无法审计"模拟过程是否被篡改"，离线 AI R20 要求的 bit 一致审计无法满足。否决。
  - **选定的根据**：① 概念 R2「所有状态以服务端为准」+ 离线 AI R22「模拟永远用服务端权威最新快照」；② 经济 §8.1 四重闸门（软上限/离线衰减/出击成本/波次消耗）需服务端结算支撑；③ 社交 R26/R28 要求经济红线与账户隔离，必须在持久化层强制；④ 回放审计是 R2 的最终兜底（PVP §3.1/§3.6）。
- **影响**：
  - 正：彻底封堵本地篡改与跨账号通胀路径（R2/R6）；离线 AI 快照权威、可审计；跨平台进度可由服务端统一（远期云存档）。
  - 负/约束：需服务端 DB 与存储运维；存档需版本迁移机制；联盟令牌系统需独立上限（社交 §5.6）且不进经济循环。
  - 待办：实现 `server/persistence/`（序列化 + 迁移）、`server/anticheat/`（心跳 + 回放比对 + 回滚）、社交令牌独立账本（架构 §5/§6）。
