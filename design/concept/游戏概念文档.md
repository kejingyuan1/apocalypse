> 阶段：Phase 1 概念孵化（Concept）

> 文档负责人：文策渊（design-strategist）｜ 用途：供 Phase 2 逐系统 GDD 拆解

## 0. 一句话定位

**在 18×18 的像素网格上，从一间避难所逐渐建成末日堡垒；一边周期性挡住丧尸潮，一边实时突袭他人堡垒——空间布局即战略，攻防双线皆为生存。**

---

## 1. 游戏支柱（Game Pillars）

> 支柱是日后所有系统评审的"宪法"。任何 GDD 若与以下支柱冲突，原则上需回炉。

| # | 支柱 | 一句话定义 | 为什么这样定（设计意图） |
|---|------|-----------|------------------------|
| P1 | **空间即策略** | 堡垒网格的布局、朝向、邻接关系本身就是核心决策，而非装饰。 | 把"建造"从传统模拟经营的放置乐趣，升级为可计算、可博弈的策略核心；区别于纯塔防与纯经营，奠定本作差异化。 |
| P2 | **双线威胁** | 玩家同时面对周期性的 PVE 丧尸潮与实时 PVP 突袭，防御与扩张必须权衡。 | 单一目标易疲劳；双威胁持续制造资源分配张力，让"何时守、何时攻"成为永恒难题。 |
| P3 | **看得见的成长** | 从 1 房间到 18×18 的扩张有清晰里程碑与密集正反馈。 | 建造/经营类玩家的核心驱动力是进度可视；像素风天然适合"逐块拼装"的可见成长。 |
| P4 | **实时对抗的快感** | 实时 PVP 提供不可预测、强反馈的对抗体验与社交叙事素材。 | 异步/离线 PVP 缺乏张力；实时权威对抗带来"正在被攻打"的肾上腺素与可炫耀战果。 |
| P5 | **低门槛高深度** | 单指/单键即可完成基础建造，深度来自布局优化与进攻时机。 | 跨平台（含移动端/Web）要求极简操作下限；同时用布局协同、进攻博弈保留硬核策略上限。 |

> 红线自检：P5 直接对冲"认知过载"风险；P1/P2 共同规避"单一主导策略"——若某布局能通吃 PVE+PVP，则需回炉。

## 2. MDA 框架分析

MDA（Mechanics–Dynamics–Aesthetics）是设计骨架。Mechanics 是给玩家的"规则零件"，Dynamics 是零件交互后的"涌现行为"，Aesthetics 是玩家最终"感受"。

### 2.1 核心动词（动词优先法 · Verb-First）

设计从"玩家能做什么动词"出发，再反推系统：

`放置(Place)` · `升级(Upgrade)` · `生产(Harvest)` · `布防(Defend)` · `出征(Raid)` · `实验(Experiment)` · `供能(Energize)`

这 7 个动词即后续 GDD 系统拆分的最小单元（建造/经济/波次/PVP/科技/能源系统一一映射）。

### 2.2 Mechanics（机制层 · 规则零件）

| 机制 | 规则要点 | 对应动词 |
|------|---------|---------|
| 网格放置 | 18×18 网格，房间按类型占不同格数；可放置/移动/拆除（拆除有冷却与损耗） | Place |
| 资源经济 | 3 种资源（废料/晶体/生物质）由生产房间随时间产出，有软上限 | Harvest |
| 房间升级 | 消耗资源提升房间等级，增强产出/防御/供能 | Upgrade |
| 能源网络 | 能源房间按半径供能；断能则范围内房间降级或停摆 | Energize |
| 威胁响应 | PVE 波次倒计时触发；玩家手动操作武器/技能抵御 | Defend |
| 出征进攻 | 组建并实时派遣单位攻击他人堡垒，战后掠夺结算 | Raid |
| 科技实验 | 实验房间解锁主动/被动能力，含分支树 | Experiment |
| 邻接协同 | 互补房间相邻触发加成（如能源邻接武器提升射速） | — |

### 2.3 Dynamics（动态层 · 涌现行为）

- **布局博弈**：防御房间置于外围形成天然防线，生产/居住内嵌，城墙砌出"迷宫"延长僵尸路径。
- **资源挤压**：升级与出征争夺同一资源池，迫使玩家在"固守"与"掠夺"间定优先级。
- **波次错峰**：PVE 周期与 PVP 事件在时间上交错，玩家需在和平期完成运营、在战时专注对抗。
- **断线脆弱**：离线堡垒仅由"自动防御 AI"托管，弱于在线手动操作——形成"在线更安全"的正向在线激励。
- **邻接涌现**：实验+能源+武器三角相邻可能涌现"超载炮塔"等隐藏 combo，构成探索深度。

### 2.4 Aesthetics（美学层 · 情感目标，按 LeBlanc 八类映射）

| 美学维度 | 本作如何交付 |
|---------|-------------|
| Challenge（挑战） | 丧尸潮难度递增 + PVP 战力分桶，持续制造的"能不能守住"张力 |
| Discovery（发现） | 科技分支、邻接隐藏协同、最优布局的反复试错 |
| Expression（表达） | 堡垒布局即玩家签名，参观他人基地即审美比较 |
| Fellowship（社群） | 实时突袭、联盟援防、排行榜、战报分享 |
| Sensation（感官） | 像素 crunch 手感、命中 juicy 反馈、霓虹能源辉光 |
| Fantasy（幻想） | "末日幸存指挥官"角色代入 |
| Narrative（叙事） | 轻量：通过废墟贴片/日志条目讲世界观，不抢玩法 |
| Submission（消遣） | 和平期放置类心流（低压力经营） |

## 3. 玩家心理学

### 3.1 自我决定论（Self-Determination Theory）

| 基本心理需求 | 满足方式 | 设计落点 |
|------------|---------|---------|
| **自主 Autonomy** | 自由规划布局、自选进攻目标、自定升级路线与科技分支 | P1 空间即策略 + P2 双线选择权；无强制线性任务链 |
| **胜任 Competence** | 挡下波次的反馈、进攻成功的战利品、里程碑解锁、连胜记录 | P3 可见成长；每波结算有"防御评分"；成就系统 |
| **关联 Relatedness** | 实时对手、联盟/好友、排行榜、基地互访、战报社群 | P4 实时对抗 + 社交系统；"被谁攻打过"成为社交货币 |

### 3.2 心流平衡（Flow Channel）

- **技能轴（玩家成长）**：操作（手动武器瞄准）→ 策略（布局/资源分配）→ 元策略（何时守/何时攻/选谁打）。
- **难度轴（挑战成长）**：PVE 波次强度随波次指数递增；PVP 按堡垒战力分桶（MMR-like）匹配。
- **心流通道设计**：
  - 早期：低波次 + 低战力对手，建立"我能行"的胜任感。
  - 中期：引入多线威胁（PVE+PVP 并行窗口），拉高挑战。
  - 后期：高难波次 + 高战力对手 + 赛季目标，维持紧张峰值。
- **动态难度缓冲（防焦虑/防无聊）**：连续失败 2 波 → 下一波强度 -10%；连续成功 3 波 → 微调 +5%。缓冲阈值写入波次系统 GDD。

## 4. Bartle 玩家类型覆盖分析

| 类型 | 在本作得到什么 | 关键系统支撑 |
|------|--------------|-------------|
| **杀手 Killer** | 实时突袭他人堡垒、掠夺资源、摧毁成就感、排行榜霸榜 | P4 实时 PVP + 战力分桶 + 战利品结算 + 赛季榜 |
| **成就者 Achiever** | 科技树全解锁、堡垒满级、波次连胜、成就/勋章收集 | P3 成长里程碑 + 成就系统 + 实验分支 |
| **探索者 Explorer** | 房间邻接隐藏协同、科技实验分支、最优迷宫布局的 discovery | 邻接协同机制 + 实验房间 + 沙盒式布局 |
| **社交者 Socializer** | 联盟、好友援防、基地参观、聊天、战报分享、排行榜社交比较 | 联盟/好友系统 + 基地互访 + 战报流 |

> 自检：四类均有明确落点，无"被遗忘的玩家"。若某类型在后续 GDD 中找不到支撑，即为支柱漂移预警。

## 5. 核心循环（Core Loop）

### 5.1 文字描述

1. **运营期（和平）**：收集资源 → 放置/升级房间 → 规划布局 → 做科技实验 → 维护能源网络。
2. **预警期**：PVE 波次倒计时 警报 / 或收到 PVP 突袭警报（HUD 双通道提示）。
3. **防御期**：手动操作武器/技能抵御 PVE 丧尸潮；若被 PVP 进攻则实时反击、激活陷阱。
4. **反攻期**：PVE 结束后（或和平窗口）派遣单位实时进攻他人堡垒，掠夺资源。
5. **结算期**：获得战利品 / 损失评估 / 防御评分 → 回到运营期，循环收紧（更强威胁）。

### 5.2 循环图结构建议（供 UX/美术对齐）

```
        ┌─────────────────────────────────────────────┐
        │                                               │
        ▼                                               │
   [运营期] ──预警──▶ [防御期 PVE波次] ──结束──┐         │
      │                                        │         │
      │                          ┌─────────────┘         │
      │                          ▼                       │
      │                   [反攻期 实时PVP] ──结算──┐      │
      │                          │                 │      │
      │                  (被进攻则切回防御期)        │      │
      │                          └─────────────────┘      │
      └──────────────────[结算期]◀───────────────────────┘

  并行事件：PVP 突袭可随时插入 → 触发"双线模式"（见 §10）
```

> 该循环是"建造→守→攻→扩张"的螺旋；每一圈威胁更强，对应 P3 可见成长。

## 6. 范围分层（Scope Tiers）

> 边界用"玩法是否服务于 P1–P5 支柱"判定；砍掉标准用"是否阻断核心循环"判定。

### 6.1 核心层（MVP · 必须可玩）

| 项 | 内容 | 砍掉标准 |
|----|------|---------|
| 建造 | 18×18 网格、6 类基础房间（防御/生产/能源/居住/实验/攻击武器） | 无法实现"放置→守→扩张"循环即砍 |
| PVE | 前 10 波本地定时波次，单机可玩 | 波次无难度递增则砍 |
| 经济 | 3 资源、生产房间产出、软上限 | 无资源稀缺感则砍 |
| 防御 | 手动操作 1–2 种武器 + 城墙阻挡 | 无手动参与则退化为看动画 |
| 平台 | PC 优先跑通，移动/Web 做基础适配 | 不做全平台打磨 |

### 6.2 延伸层（Extended · 上线必需）

| 项 | 内容 |
|----|------|
| 实时 PVP | 服务器权威、突袭他人堡垒、战利品结算 |
| 离线防御 AI | 玩家离线时堡垒自动防守、护盾机制 |
| 科技树 | 实验房间分支解锁主动/被动能力 |
| 社交 | 联盟/好友、基地互访、排行榜（基础） |
| 扩展房间 | 医疗/仓储/指挥等（见 §7） |

### 6.3 远期层（Long-term · 赛季/运营）

| 项 | 内容 |
|----|------|
| 跨平台云存档 | Steam/移动/Web 进度同步 |
| 赛季系统 | 排行榜重置、赛季奖励、平衡性赛季调整 |
| 世界事件 | 地图级 Boss、全服协作/竞争事件 |
| UGC/模组 | 玩家自定义房间、布局分享码 |
| 观战/回放 | PVP 实时观战、战斗回放审计 |

> 红线：任何层不得引入"经济失衡"（产出≫消耗）或"认知过载"（同时可决策项爆炸）。

## 7. 房间类型与空间占用提案（面积矩阵）

> 网格基础单位 = 1 格（cell）。最大堡垒 18×18 = 324 格。面积差异是核心取舍来源：**大房间占战略位但挤占生产/居住；小房间灵活但单体能力弱。**

### 7.1 面积矩阵表

| 房间类型 | 尺寸（宽×高·格） | 占格数 | 功能定位 | 面积设定理由 |
|---------|----------------|-------|---------|------------|
| 城墙 Wall | 1×1 | **1** | 阻挡/延长僵尸路径、拼迷宫 | 最小单元，用于"以空间换时间"的布局博弈 |
| 人口居住 Housing | 2×2 | **4** | 提供人口上限（劳动力/防守员） | 小且密集，鼓励内嵌堆叠 |
| 能源 Energy | 2×2 | **4** | 半径供能，断能降级 | 小以便贴近多房间布网 |
| 攻击武器 Turret | 2×2 | **4** | 手动/自动火力点，需射界 | 单体紧凑，靠数量与位置弥补 |
| 生产 Production | 3×2 | **6** | 持续产出资源 | 中等，需占内部稳定区 |
| 医疗 Medical* | 2×3 | **6** | 战斗中修复房间/单位 | 中等，需临近防线 |
| 仓储 Storage* | 3×2 | **6** | 提升资源软上限 | 中等，内部缓冲 |
| 防御 Defense | 3×3 | **9** | 掩体/减速/范围拒止 | 大，强制占外围战略点 |
| 实验 Lab | 3×3 | **9** | 解锁科技分支 | 大且需稳定供能，牵制布局 |
| 指挥 Command** | 4×4 | **16** | 堡垒核心，被毁=失败 | 唯一且最大，天然成为攻防焦点 |

`*` 延伸层房间　`**` 全游戏唯一，初始即存在（见 §8）

### 7.2 为何不同面积（设计逻辑）

- **稀缺制造决策**：324 格上限下，16 格指挥 + 多个 9 格防御/实验 会迅速吃满网格，逼迫"防御 vs 生产 vs 实验"的三角取舍——直接服务 P1/P2。
- **位置绑定价值**：大房间（防御/实验）必须贴边/贴核心才有战略意义，小房间（城墙/能源）用于填空与连线，形成"骨架大件 + 填充小件"的拼装美学（呼应 P3 与视觉锚点 §11）。
- **升级替代扩张**：后期格子紧缺时，靠"升级房间"而非"加房间"突破，避免 18×18 填满后无决策（见风险 R5）。

## 8. 堡垒生长曲线（1 房间 → 18×18）

> 扩张由"堡垒等级"门控，等级靠"存活波次 + 资源投入"提升。资源：废料(Scrap)/晶体(Crystal)/生物质(Biomass)。

### 8.1 生长里程碑表

| 堡垒等级 | 可用网格 | 房间数上限 | 解锁内容 | 资源门槛（累计） | 关键里程碑 |
|---------|---------|-----------|---------|----------------|-----------|
| Lv1 | 6×6 | 4 | 居住+生产+城墙 | —（初始） | 挺过第 1 波 |
| Lv2 | 8×8 | 7 | 能源 + 防御 | 废料×200 | 建成首条能源网 |
| Lv3 | 10×10 | 11 | 武器 + 实验 | 废料×600, 晶体×150 | 解锁科技分支 |
| Lv4 | 13×13 | 16 | **解锁 PVP 出征** + 医疗 | 废料×1500, 晶体×500, 生物质×200 | 首次突袭他人堡垒 |
| Lv5 | 15×15 | 20 | 仓储 + 多线威胁 | 废料×4000, 晶体×1500, 生物质×800 | 承受双线（PVE+PVP） |
| Lv6(Max) | 18×18 | 30 | 满级房间 + 赛季目标 | 废料×10000, 晶体×4000, 生物质×2500 | 满级堡垒 |

### 8.2 扩展节奏

- **触发**：每存活 3 波 → 堡垒等级 +1（自动建议扩张）；玩家也可消耗资源提前申请升级。
- **起点（M0）**：1 个"核心舱"= 指挥(4×4) 雏形 + 临时居住功能，随 Lv2 拆分独立房间。
- **节奏设计**：前 3 级快（约 10 分钟内可达 Lv3，建立正反馈）；Lv4–Lv6 慢（需数十波 + 资源积累），维持长线目标。
- **反漏斗**：等级越高，单次升级资源成本指数增长（≈1.6× 每级），制造"后期每级都难"的胜任感曲线。

## 9. 丧尸入侵波次模型

### 9.1 模型参数

- **入侵周期**：和平期 `T = 90s`（移动/Web 友好；PC 可设 60s 硬核档）。
- **强度公式**：
  - 数量 `N(w) = round(8 × 1.12^(w−1))`
  - 单兵 HP `HP(w) = 20 × (1 + 0.15×(w−1))`
  - 波次总威胁 `TH(w) = N(w) × HP(w) × 类型系数`
- **类型系数**：普通 1.0 / 快速 0.8(脆但快) / 装甲 1.8(慢但厚) / 喷吐 1.3(远程)。

### 9.2 前 10 波示例表

| 波次 | 间隔 | 僵尸组成 | 数量 | 波次总HP(约) | 特殊机制 | 推荐防御应对 |
|------|------|---------|------|------------|---------|------------|
| W1 | 90s | 普通×8 | 8 | 160 | 无 | 1 武器塔 + 城墙引导 |
| W2 | 90s | 普通×9 | 9 | 180 | 首只快速 | 补 1 能源保射速 |
| W3 | 90s | 普通×10 + 快速×2 | 12 | 256 | — | 双塔交叉射界 |
| W4 | 90s | 普通×11 + 装甲×1 | 12 | 320 | 首只装甲 | 集中火力破甲 |
| W5 | 90s | 普通×12 + 快速×4 | 16 | 384 | 小股分流 | 迷宫延长路径 |
| W6 | 90s | 普通×13 + 装甲×2 | 15 | 520 | — | 实验房解锁减速 |
| W7 | 90s | 普通×14 + 快速×6 | 20 | 512 | 双路夹击 | 外围防御+内线预备 |
| W8 | 90s | 普通×15 + 装甲×3 | 18 | 720 | 首只喷吐 | 优先点掉远程 |
| W9 | 90s | 全类型混合×22 | 22 | 880 | 三路进攻 | 指挥核心护盾就绪 |
| W10 | 90s | 普通×16 + 快速×8 + 装甲×3 + 喷吐×2 | 29 | 1180 | Boss 前兆 | 满防 + 手动操作 |

### 9.3 与堡垒防御的对抗关系

- **攻防等式**：若 `堡垒总DPS × 波次时间窗口 ≥ TH(w)` → 守住；否则破防（僵尸触及指挥核心）。
- **设计张力**：玩家不能无限堆 DPS（格子/资源有限），必须用城墙迷宫"延长接触时间"、用能源协同"提升单位 DPS"、用布局"引导集火"——把数值对抗转化为空间博弈（P1）。
- **失败后果**：核心受损 → 资源损失 + 等级停滞；核心被毁 → 堡垒重置至 Lv2（软惩罚，非删档），避免挫败崩盘。

## 10. 实时 PVP 对玩法的约束分析（服务器权威）

### 10.1 服务器权威下的能力边界

| 角色 | 能做什么 | 不能做什么 |
|------|---------|-----------|
| **进攻方** | 实时派遣单位进入对方网格；手动操控走位/集火；瘫痪能源或防御房间以削弱；战后按结算掠夺资源 | 不能直接改对方布局（只读）；不能穿墙瞬移（路径服务端校验）；离线目标不可强攻（走护盾） |
| **防守方（在线）** | 手动操作防御武器反击；激活陷阱/技能；实时看到进攻单位并切换应对 | 不能反向控制进攻方单位；不能临时改建（战斗中布局锁定） |
| **防守方（离线/断线）** | 堡垒由"自动防御 AI"托管（预设武器自动开火、城墙阻挡） | 无法手动微操；护盾 CD 内仅损失少量资源 |

### 10.2 离线 / 断线处理

- **离线**：堡垒进入"托管防御"模式，按玩家预设的"自动开火优先级"运行；设 **离线护盾**（每日 1 次，免战 8h），护盾外仅损失 ≤5% 资源，杜绝"睡觉被搬空"。
- **断线**：服务器继续模拟至战斗结束并结算；重连后可看"战斗回放"；不奖励断线逃避（断开即判防守失败但护盾仍生效）。
- **防作弊兜底**：所有状态以服务端为准，客户端仅发送输入（见风险 R2）。

### 10.3 对核心循环的影响

- 反攻期从"异步点击"升级为"实时操控"，紧张感与社交叙事素材大增（P4）。
- 新增必运营项：**自动防御预设**（离线也能守），使和平期多一层策略深度。
- 要求 HUD 区分"运营/防御/反攻"三态，避免认知过载（P5）。

### 10.4 PVP 与 PVE 如何共存不冲突

- **时间分桶**：PVE 波次为固定周期（90s）；PVP 突袭为实时事件，但**仅可在对方"非波次期（和平窗口）"发起**。
- **误撞处理**：若进攻方发起时目标恰入 PVE 波次 → 进攻排队或目标获"战时加成"（防御 DPS +20%），优先保障 PVE 体验，避免双重惩罚。
- **双线模式**（仅限双方均在线且主动开启）：HUD 分区显示两路，服务器并行模拟，结果独立结算——作为高玩可选模式，非默认。
- **结论**：通过"和平窗口才可进攻 + 战时加成"，PVP 与 PVE 在时间与规则上解耦，互不挤占（规避 P2 疲劳与认知过载）。

## 11. 视觉锚点关键词（供 art-director 对齐）

> 以下关键词用于美术风格对齐，请勿在文档阶段定死色值，留给美术圣经（Art Bible）细化。

1. **废土霓虹 Wasteland Neon** — 暗调废土底色 + 能源/武器的霓虹高光对比。
2. **低饱和棕绿 Desaturated Olive/Brown** — 主色调脏旧、末日感。
3. **32×32 像素密度** — 基础 tile 尺寸由美术圣经定为 32×32，概念阶段不锁死视觉细节。（采纳美术建议：多平台尤其移动端小屏可读性、房间需表现管道/家具/表情、640×360 设计分辨率下 32px tile≈20×11 格契合经营视角、现代像素经营游戏普遍 32 基准）
4. **厚涂硬阴影块 Chunky Shadow Bands** — 像素硬阴影表现体积。
5. **危险暖橙 Hazard Amber** — 僵尸/威胁/警报用橙红。
6. **冷蓝能量 Cold Energy Cyan** — 能源/科技/护盾用青蓝。
7. **模块化拼装感 Modular Silhouettes** — 房间像集装箱/预制板拼装。
8. **动态腐蚀贴片 Dynamic Grime** — 受伤墙体、血迹、锈迹可叠加 decal。
9. **俯视微厚 Top-down + Thickness** — 网格俯视但房间带侧面厚度（2.5D 微透视）。
10. **可读性优先 Readability > Realism** — 小尺寸下优先辨识度（敌我/资源/状态一目了然）。

## 12. 已知设计风险与缓解

| # | 风险 | 严重度 | 缓解策略 |
|---|------|-------|---------|
| R1 | **实时 PVP 平衡**：高战力玩家碾压新手，劝退 | 高 | 战力分桶匹配（MMR）；进攻收益衰减（打弱目标收益↓）；防守方离线护盾；新手期（<Lv4）关闭被进攻 |
| R2 | **作弊 / 服务器权威**：客户端篡改（加速、无限资源、穿墙） | 高 | 服务器权威所有状态；客户端仅发输入；移动/资源服务端重算；反作弊心跳 + 战斗回放审计 |
| R3 | **双威胁认知过载**：PVE+PVP 并行致玩家 overwhelmed | 中 | 时间分桶 + 双线模式 HUD 分区；新手期关 PVP；动态难度缓冲（§3.2） |
| R4 | **跨平台操作不一致**：移动端小屏难精准放格 | 中 | 网格吸附+缩放；拖拽+长按；统一"放置/升级/进攻"三动词抽象层跨端一致（P5） |
| R5 | **后期格子填满后无决策**（支柱漂移） | 中 | 房间升级替代无限扩张；邻接协同奖励；武器"射界/视野"限制制造布局张力；赛季重置/重构活动 |
| R6 | **经济失衡**：生产≫消耗，资源通胀 | 中 | 资源软上限；离线产出衰减；进攻消耗弹药/能源；PVE 波次消耗存量 |

> 红线追踪：R1/R2 直击实时 PVP 的"平衡/作弊"双风险；R3/R5/R6 分别对冲"认知过载/支柱漂移/经济失衡"——四类设计红线均有对应缓解。
